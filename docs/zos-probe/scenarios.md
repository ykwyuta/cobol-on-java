# z/OS 実機での挙動調査 — シナリオ一覧

暫定判断 (`docs/decisions/provisional.md`) のうち、**解消条件が「実機で確かめる」になっているもの**を
1 つずつ問いに落とし、実機で流す原文 (`tools/zos-probe/`) に対応させた一覧である。
流し方は [runbook.md](runbook.md) にある。

## 0. この一覧の読み方

各行は次の 4 つを持つ。

| 欄 | 中身 |
| --- | --- |
| 事例 | `ProbeTool prb` が突き合わせる名前。`<ジョブ>/<ステップ>` と事例名の頭 |
| 問い | 実機に答えてもらうこと。**1 つの行に問いは 1 つ** |
| 今の処理系 | `run-local.sh` で採った、この処理系の答え。`results/local/` にそのまま残してある。2026-09-23 に採り、§7 の不備を直した 2026-09-24 に採り直した |
| 決着 | 実機の答えで、暫定判断がどう動くか |

「今の処理系」は**予想ではなく観測**である。暫定判断に書いてある規則を読んで書いたのではなく、
同じ原文を流して採った。暫定判断の記述と観測が食い違っていれば、それ自体が見つかった不備である
(§7 に並べた)。

### 観測の形

どの probe も、結果を 1 行ずつ次の形で出す。

```
PRB <事例名> <16進> |<参考の文字>|
```

**照合は 16 進で行う。**文字は SYSOUT を取り出すときのコードページ変換を通るので、観測に
変換が混ざる。16 進を持たない行 (状態や件数) だけ文字で比べる。

16 進は、観測する項目を群で包み、群の転記 (英数字の転記) でバイトを取り出してから作る。
数字項目を直に英数字へ `MOVE` すると、符号が落ちるなど**転記の規則が観測に混ざる**からである。

### 変種

同じ原文を翻訳オプションや実行時オプションを変えて流すものがある。実機では別のロードモジュール
(`CBLNUMP` など) になり、ステップ名で区別する。ローカルでは、この処理系の翻訳が `NUMPROC` /
`ARITH` / `ADV` / `NUMBER` / `RENT` を効かせず、結果を変える値 (`NUMPROC(PFD)`、`ARITH(EXTEND)` など) は翻訳で断る (P-023)。そこで変種のステップでも元のクラスを流す。
**実機の変種同士に差があり、ローカルに差がなければ、そのオプションは効かせなければならない**
ということである。`SSRANGE` だけはこの処理系でも効くので、ローカルでも翻訳し直して流す。

## 5. JCL {#jcl}

JCL の probe は**同じ JCL をこの処理系のジョブ実行でもそのまま流す** (`JOBLIB` / `STEPLIB` の行を
注記の行に置き換えるだけで、行番号は変えない)。すべてのジョブは 1 つのデータセットの置き場
(目録) で、手順書の順に流す。観測は、ステップが流れたか、完了コード、データセットの結末である。
実機の欄は JES のメッセージ (`IEF142I`、`IEF272I`、`IEF285I`、`IEF377I` など) から埋める。

「今の処理系」の欄は 2026-09-24 の観測である (ジョブ実行が SYSIN / SYSOUT の DD を結ぶように
なったあと。§7 の 1)。

### 5.1 条件 (`JCLCOND`、`JCLCONR`)

| ステップ | 仕掛け | 実機の予想 (JCL の手引きから) | 今の処理系 |

| `S02` | `COND=(4,LT)`、前は RC 4 | 流れる | 流れる |
| `S04` | `COND=(8,LE,S03)`、S03 は RC 8 | 飛ばす | 飛ばす |
| `S05` / `S06` | `IF (S03.RC = 8)` / `ELSE` | S05 | S05 |
| `S07` → `S08` | 異常終了のあとの普通のステップ | S08 は FLUSH | S07 が S0C7、S08 は流れない |

## 7. probe を作る途中で分かった、この処理系の不備

実機を待たずに分かったものである。probe を**実機で正しい書き方**で書き、ローカルで流したら
出た。暫定判断に書かれていないものがほとんどであり、「自分で書いた規則は、自分のテストでは
破れない」(CLAUDE.md §3) の例になっている。

2026-09-24 に、直せるものは直した。**14 件のうち 2 件と半分は処理系の不備ではなかった**。
2 件は probe の道具 (`run-local.sh`) の誤りであり (CLAUDE.md §6: 検査の道具が処理系の失敗を
作ってはならない)、1 件は規則どおりの値だった。

| # | 見つかったこと | どこで | 状態 (2026-09-24) |
| --- | --- | --- | --- |
| 1 | ジョブ実行が `ACCEPT` をステップの `//SYSIN DD` へ結ばず、プロセスの標準入力を読む。`DISPLAY` も `//SYSOUT DD` へ行かない | `CBLRC` などを `cobolj` で流したとき | **直した** (92976c3)。SYSIN を様式どおりにレコードへ切って読み、DISPLAY は SYSOUT の DD へ書く |
| 2 | 主プログラムの `PARM` は、連絡節の長さと**ちょうど同じ**長さでないと呼出しの前に断る | `CBLPARM` | **直した** (92976c3、P-090)。連絡節の宣言した長さまで領域を取って渡し、PARM が無ければ長さ 0 の欄を渡す |
| 3 | `DISP` を書かない DD が既存の目録つきデータセットを指すと、ステップが流れ、終わるとそれを消す | `JCLDISP2` | **道具の誤りだった**。`run-local.sh` がジョブごとに別のデータセット置き場を使っていたので、`JCLDISP2` から `DISP.A` が見えなかった。処理系は既存の名前への `NEW` を `IEF344I` で止める。置き場を 1 つにした |
| 4 | 同じジョブの中で `DEFINE GDG` したあとの `(+1)` を「GDG ではない」と断る | `JCLGDG` | **直さずに実機に問う**。設計 90 は「ホストにも同じ制限がある」として意図して断っており、既存の試験もそれを固定している。どちらが正しいかは実機で確かめていないので、確かめないまま受け入れる側へ倒さない。問いを `JCLGDGD` に切り出し、ほかの GDG の問いが測れるよう基底の定義を `JCLGDG0` に分けた |
| 5 | `IF (x.RUN = TRUE)` と `IF (NOT ABEND)` を読めず、ジョブ全体を断る。誤りの行を `ENDIF` の行として報告する | `JCLCONR` | **前半を直した** (31ca3fc、P-046)。`= TRUE` / `= FALSE` / `¬= TRUE` を読む。`NOT ABEND` はもともと読めていた。**後半は道具の誤りだった** (`//JOBLIB` の行を削って行番号をずらしていた)。削らずに注記の行へ置き換えるようにした |
| 6 | PL/I の `INIT(-12345)` / `INIT(-7)` が 0 になる | `PLISTRM` `S03` `S05` | **直した** (e3d0d6c)。INIT の中身を式として読む |

### 変種の読み方が変わった

14 を直したので、`NUMPROC(PFD)`、`NUMPROC(MIG)`、`ARITH(EXTEND)` の変種はこの処理系では
**翻訳で断られる**。`run-local.sh` は変種のステップでも元のクラスを流すので、`NUMP`、`NUMM`、
`FUNE`、`FUNX` のローカルの観測は「オプションを効かせない場合の値」である。実機との `DIFF` が
そのまま「そのオプションを実装しなければならない量」になる。
