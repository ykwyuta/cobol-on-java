## 1. はじめに

### 1.1 本書の目的

本書は、JVM (Java Virtual Machine) 上で動作する COBOL 処理系「cobol-on-java」の要件を定義する。
本プロジェクトの最大の特徴は、**単に COBOL 言語仕様を実装するのではなく、IBM メインフレーム
(z/OS + Enterprise COBOL for z/OS + Language Environment) 上での実行時の「振る舞い」を可能な限り
忠実に再現する**ことにある。これにより、既存メインフレーム資産を「書き換えずに」JVM 上へ
移行できることを狙う。

### 1.2 本書の位置付け

本書は要件 (What) を定義する。設計 (How) は別途 `docs/design/` 配下の設計文書で定義する。
本書で定義した要件 ID (FR-xxx / NFR-xxx / CMP-xxx) は、設計文書・テストケース・課題管理から
トレーサビリティを維持できるよう参照される。

### 1.3 用語定義

| 用語 | 定義 |
| --- | --- |
| ホスト / メインフレーム | IBM z/OS が稼働する System z 系メインフレーム環境 |
| 参照実装 | 互換性の基準とする IBM Enterprise COBOL for z/OS 6.x + Language Environment |
| 移行元プログラム | ホスト上で稼働している既存 COBOL ソースおよび関連資産 |
| 本処理系 | 本プロジェクトが開発する COBOL コンパイラ + ランタイムの総称 |
| EBCDIC | IBM メインフレームで用いられる文字コード体系。本書では特に IBM-1047 / IBM-930 / IBM-939 等を指す |
| ゾーン10進数 | USAGE DISPLAY の数値項目。1 桁 1 バイトで符号をゾーン部に持つ形式 |
| パック10進数 | USAGE COMPUTATIONAL-3 (COMP-3)。1 バイト 2 桁 + 末尾 4 ビットに符号を持つ形式 |
| LE | Language Environment。z/OS の言語共通ランタイム基盤 |
| ABEND | Abnormal End。異常終了。システム ABEND (Sxxx) とユーザ ABEND (Uxxxx) がある |
| QSAM / VSAM | z/OS のデータセットアクセス法。順次編成 / 索引・相対・入力順編成 |
| バイト忠実 | メモリ上・ファイル上のバイト列が参照実装と 1 バイトも違わないこと |

### 1.4 参考仕様と検証手段

**規範となる仕様書**

- ISO/IEC 1989:2014 (COBOL 2014)、ISO/IEC 1989:2002、ANSI X3.23-1985 (COBOL 85)
- IBM Enterprise COBOL for z/OS 言語解説書 / プログラミング・ガイド (6.x 系)
- IBM z/OS Language Environment プログラミング・ガイド / ランタイム・メッセージ
- IBM z/Architecture Principles of Operation (10 進演算・編集命令・条件コードの挙動)

**検証に用いる実装 (オラクル)**

- **Hercules** — オープンソースの System/370・ESA/390・z/Architecture エミュレータ。
  本プロジェクトが利用できる唯一の実行オラクルであり、機械語命令レベルの挙動を採取する
  (第 4.2 節)。
- NIST COBOL-85 検証テストスイート (CCVS85, パブリックドメイン)
- 公開されている OSS の COBOL ソース資産 (構文網羅率の測定に用いる)

**重要な前提**: IBM は Hercules 上での z/OS の実行をライセンスしていないため、
**参照実装である Enterprise COBOL 6.x のコンパイラ本体は入手できない**。
Hercules 上で合法的に実行できるのはパブリックドメインの MVS 3.8j 世代までであり、
これは Enterprise COBOL とは世代が大きく異なる。したがって Hercules は
「COBOL 処理系のオラクル」ではなく「**z/Architecture 命令のオラクル**」として用いる。
この制約が検証範囲に与える影響は第 4.2 節で定義する。

### 1.5 知的財産に関する前提

本処理系は IBM 社の製品ソースコードを一切参照せず、公開仕様書および観測可能な
外部挙動のみに基づくクリーンルーム実装とする。IBM、z/OS、z/Architecture、CICS、Db2、IMS、
MVS、Enterprise COBOL は IBM 社の商標であり、本プロジェクトは IBM 社とは無関係である。
互換性の主張は「観測された外部挙動の再現」に限定し、認証・保証を意味しない。

**Hercules の利用範囲について**: Hercules は Q Public License (QPL) で提供されており、
本プロジェクトのライセンス (Apache-2.0) とは互換性がない。したがって Hercules は
**実行して結果バイト列を採取する外部オラクルとしてのみ利用し、そのソースコードを読んで
実装を写すことは行わない**。この境界は開発規約として明文化し、レビューで担保する。

## 2. 背景と目的

### 2.1 背景

メインフレーム上の COBOL 資産は依然として基幹業務の中核を担う一方、以下の課題を抱える。

1. **コスト構造**: MIPS 課金・保守費用の継続的な負担。
2. **人材**: COBOL および z/OS 運用に精通した技術者の減少。
3. **連携性**: クラウドネイティブなシステム群との接続に専用ゲートウェイが必要。
4. **移行リスク**: 手作業による Java 等への書き換えは、桁あふれ・丸め・文字コードといった
   微細な挙動差から業務障害を招きやすく、テスト工数が莫大になる。

課題 4 が本プロジェクトの主眼である。**ソースを書き換えないこと**が、移行リスクを最小化する
最も確実な手段であるという前提に立つ。

### 2.2 目的

| # | 目的 | 達成の判定基準 |
| --- | --- | --- |
| G-1 | 既存 COBOL ソースを無修正または極小修正で JVM 上で実行可能にする | 対象資産の 95% 以上がソース修正なしでコンパイル成功 |
| G-2 | ホストと同一の入力に対し同一の出力 (バイト列) を得る | 検証レベル V2 (第 4.2 節) に到達した領域で採取済み期待値と 100% 一致。実機との並行稼働突合は本プロジェクト単体では実施できないため、移行プロジェクト側の手順 (UC-4) と位置付け、本プロジェクトは突合ツール (FR-196) の提供をもって責務とする |
| G-3 | 障害時の挙動 (ABEND・ファイル状態コード) も再現する | 定義した異常系シナリオの 100% で同等コードを返す |
| G-4 | Java エコシステムとの相互運用を可能にする | COBOL ⇔ Java 双方向呼び出しが動作 |
| G-5 | 移行の判断材料となる非互換点を静的に検出・報告する | 診断レポートで非互換要素を漏れなく列挙 |

### 2.3 スコープ外 (非目標)

以下は本プロジェクトの目標としない。将来の拡張候補としては記録するが、要件には含めない。

- z/OS そのもののエミュレーション (OS カーネル、ハードウェア命令セットの完全再現)
- CICS / IMS / Db2 サブシステムそのものの再実装 (連携インタフェースの提供に留める)
- アセンブラ (HLASM) プログラムの実行 (呼び出し境界での代替実装フックのみ提供)
- PL/I、REXX、Fortran など COBOL 以外の言語処理系
- ホストからの資産の自動抽出・移送ツール (別プロジェクトとして扱う)
- 独自の COBOL 言語拡張の考案 (互換性を損なうため、原則として行わない)

## 3. ステークホルダと利用シナリオ

### 3.1 ステークホルダ

| ステークホルダ | 関心事 |
| --- | --- |
| 移行プロジェクト責任者 | 移行可否の判断、リスク、工数、非互換点の可視化 |
| 業務アプリ保守担当 | 既存ソースがそのまま動くか、デバッグができるか |
| 基盤・運用担当 | ジョブ実行方式、監視、ログ、性能、リソース消費 |
| Java 開発者 | 既存 COBOL ロジックの再利用、API 化 |
| 本処理系の開発者 | 要件の明確さ、テスト可能性、拡張ポイント |

### 3.2 主要な利用シナリオ

- **UC-1 バッチジョブの移行**: JCL で起動されていた COBOL バッチを、JVM 上のジョブ実行機構から
  同等の DD 割当・SYSIN/SYSOUT で実行する。
- **UC-2 オンライン処理の移行**: CICS トランザクションを、Web アプリケーションサーバ上の
  トランザクションとして実行する (段階的目標)。
- **UC-3 業務ロジックの API 化**: 既存 COBOL サブプログラムを Java から直接呼び出し、
  REST API のバックエンドとして再利用する。
- **UC-4 並行稼働検証**: 同一入力をホストと本処理系の双方に投入し、出力を突合して等価性を検証する。
- **UC-5 開発・保守の継続**: 移行後も COBOL のまま保守を継続し、IDE でステップ実行する。

## 4. 互換性レベルと検証レベルの定義

本プロジェクトでは、**「どこまで一致させることを目指すか」(互換性レベル)** と、
**「その一致にどれだけ裏付けがあるか」(検証レベル)** を独立した 2 軸として管理する。
参照実装 (Enterprise COBOL 6.x) の実機が利用できない以上、この 2 つを混同すると
達成できない約束を要件として抱え込むことになるため、明確に分離する。

### 4.1 互換性レベル (L0〜L3)

「IBM ホストと互換」という要件を検証可能にするため、互換性を 4 段階で定義する。
各機能要件には、達成すべき互換性レベルを明記する。

| レベル | 名称 | 定義 |
| --- | --- | --- |
| **L3** | バイト忠実 | メモリ上およびファイル上のバイト列が参照実装と完全一致する。桁あふれ・丸め・符号ニブル・充填文字まで一致 |
| **L2** | 観測等価 | プログラムから観測可能な結果 (値、条件分岐、状態コード、例外) が一致する。内部表現の差は許容 |
| **L1** | 機能等価 | 正常系の業務結果は一致するが、異常系や境界の挙動に文書化された差異がある |
| **L0** | 未対応 | 実装しない。コンパイル時に明示的な診断メッセージを出す |

**原則**: データ表現・算術・文字コード・ファイル I/O は **L3**、
制御構造・呼び出し規約は **L2** 以上を必須とする。
L1 / L0 とする機能は、必ず本書の第 11 章 (制約事項) に列挙し、コンパイラが検出可能とする。

### 4.2 検証レベル (V0〜V2)

互換性レベルは目標であり、達成の裏付けとは別である。すべてのテストケースに以下の
検証レベルを付与し、リリースノートで集計を公開する。

| レベル | 名称 | 定義 |
| --- | --- | --- |
| **V2** | 実行検証済 | オラクル (Hercules) 上での実行により期待値を採取し、照合済み |
| **V1** | 仕様準拠 | 公開仕様書の記述に基づく期待値。実行による裏取りがない |
| **V0** | 未検証 | 推定に基づく、または未着手 |

**V2 の正確な意味**: V2 は「**Hercules と一致**」であって「実機と一致」ではない。
Hercules プロジェクト自身が、実機 (real iron) を持たない場合の期待値の妥当性確認は
最も困難な工程であり、Principles of Operation の記述に曖昧さが残りうると明記している。
Hercules は数十年の運用実績と自前の回帰スイートを持つため実用上の信頼性は高いが、
この一段の間接性は互換性を主張する際に省略しない (リスク R-9)。

### 4.3 Hercules オラクルの適用範囲

Hercules は z/Architecture の命令を実装しているため、**L3 要件の相当部分は
「コンパイラの挙動」ではなく「機械語命令の挙動」に還元でき、V2 に到達できる**。
ホストの数値編集が `ED` / `EDMK` 命令そのものであり、10 進演算が `AP` / `SP` / `MP` /
`DP` / `SRP` 命令そのものである、という事実を利用する。

**V2 到達可能 (命令の挙動に還元できる領域)**

| 要件 | 対応する機械語命令 |
| --- | --- |
| FR-031 パック10進・ゾーン10進の表現と符号ニブル | `PACK` `UNPK` `ZAP` `CVB` `CVD` |
| FR-040 / FR-042 10 進演算と丸め | `AP` `SP` `MP` `DP` `SRP` `CP` |
| FR-030 PICTURE 編集 (`Z` `*` `,` `CR` `DB` `$` 等) | `ED` `EDMK` |
| FR-032 COMP-1 / COMP-2 の 16 進浮動小数 (HFP) | HFP 命令群 (`AE` `AD` `ME` `DE` 他) |
| FR-046 / FR-053 EBCDIC 照合順序と比較 | `CLC` `CLI` |

**V1 に留まる (コンパイラ・ランタイム・製品固有の領域)**

FR-041 (`ARITH` の中間結果桁数)、FR-045 (`TRUNC`)、FR-033 (`NUMPROC`)、
FR-070 / FR-071 (組み込み関数)、FR-103 (FILE STATUS コード)、
FR-140〜143 (LE / ABEND)、FR-150〜164 (Db2 / CICS / IMS)、
FR-051 のうち日本語コードページ (DBCS は MVS 3.8j 世代に存在しない)。

**V2 検証は OS を介さない**。Hercules はスタンドアロン実行が可能であり、かつ
命令レベルの回帰テスト機構をソースツリー内に持つ。合成ジェネレータ (NFR-041) が
命令列と期待状態を直接生成してこれに流し込む方式を採ることで、MVS 3.8j の導入と
その上の COBOL コンパイラのライセンス上の位置付けという問題を完全に回避する。
具体的な採取パイプラインは次節で定義する。

### 4.4 V2 期待値の採取パイプライン

Hercules のテスト機構 (`tests/` ディレクトリ、`.tst` スクリプト) をそのまま基盤として用いる。

**機構**

Hercules は `-r <script>` でスクリプトを与えてスタンドアロン起動できる。スクリプトは
Hercules コンソールコマンドと、テスト用ディレクティブ (`*Testcase` / `*Compare` /
`*Want` / `*Done`) からなるプレーンテキストである。典型的な流れは以下のとおり。

| 段階 | コマンド | 役割 |
| --- | --- | --- |
| 初期化 | `sysclear`、`mainsize`、`numcpu`、`archlvl z/Arch`、`cr 0=...` | マシン状態とアーキテクチャモードの設定 |
| ロード | `loadcore "xxx.core"` | **バイナリのコアイメージを主記憶へ直接ロード** |
| 実行 | `runtest <秒>` | 再始動割込みで実行を開始し、全 CPU 停止で制御を戻す |
| 読み出し | `r <アドレス>.<長さ>`、`gpr`、`fpr` | 記憶域・汎用レジスタ・浮動小数レジスタをコンソールへ出力 |
| 照合 | `*Want "<説明>" <期待16進>` | 期待値との突合 (`redtest.rexx` が判定) |

**要件**

- **FR-210**: 合成ジェネレータ (NFR-041) は、テストケースごとに
  (a) 命令列とオペランドを含むコアイメージ (`.core`) と、
  (b) 初期化・ロード・実行・読み出しを記述した `.tst` スクリプトを生成する。
- **FR-211**: 機械語の組み立ては本プロジェクト内で行い、外部アセンブラに依存しない。
  対象となるのは SS 形式の 10 進命令 (`AP` `SP` `MP` `DP` `ZAP` `CP` `SRP` `ED` `EDMK`
  `PACK` `UNPK` `MVO` 等) と、それらを駆動する少数の RR / RX 形式命令に限られ、
  いずれも固定長・固定レイアウトであるため、生成器内に小さなエンコーダを持てば足りる。
  (外部アセンブラを使う場合の候補は SATK の ASMA だが、必須ではない。)
- **FR-212**: **採取と回帰で同一の機構を用いる。**
  - *採取モード*: `*Want` を書かずに実行し、コンソール出力 (`allTests.out` 相当) から
    `r` コマンドの出力をパースして結果バイト列を得る。
  - *回帰モード*: 採取した値を `*Want` として `.tst` に焼き込み、リポジトリに固定する。
    以後の回帰テストはオラクルなしで実行できる。
- **FR-213**: オラクルとして用いる Hercules のバージョンとビルド構成を固定し、
  採取済み期待値と対応付けて記録する。オラクルのバージョンを更新する際は、
  既存の期待値を再採取して差分を確認する。

## 5. 機能要件: 言語仕様

### 5.1 基準となる言語レベル

- **FR-001 (L3)**: 参照実装として IBM Enterprise COBOL for z/OS 6.x が受理する言語仕様を
  ベースラインとする。ANSI COBOL 85 を中核とし、COBOL 2002/2014 のうち Enterprise COBOL が
  採用した機能、および IBM 独自拡張を対象に含める。
- **FR-002 (L3)**: 固定形式 (カラム 1-6 一連番号領域、7 標識領域、8-11 A 領域、12-72 B 領域、
  73-80 識別領域) を既定でサポートする。自由形式 (`FREE`) も選択可能とする。
- **FR-003 (L3)**: 標識領域の継続行 (`-`)、注釈行 (`*`)、デバッグ行 (`D`)、
  改ページ (`/`) を参照実装と同一に解釈する。特に文字定数の途中で継続する場合の
  空白補完規則を再現する。
- **FR-004 (L2)**: 予約語・文脈依存語の集合を参照実装に合わせる。参照実装で予約語である語を
  利用者定義語として使っているソースは、同等のエラーを報告する。

### 5.2 プログラム構造

- **FR-010 (L2)**: IDENTIFICATION / ENVIRONMENT / DATA / PROCEDURE の 4 DIVISION、
  および各 SECTION・段落の構造を完全にサポートする。
- **FR-011 (L2)**: ネストプログラム (`PROGRAM-ID` の入れ子)、`COMMON`、`GLOBAL`、
  `EXTERNAL` 属性のスコープ規則を再現する。
- **FR-012 (L2)**: `INITIAL` 指定プログラムの初期化セマンティクス、`RECURSIVE` 指定と
  `LOCAL-STORAGE SECTION` の再帰呼び出しごとの領域確保を再現する。
- **FR-013 (L3)**: `WORKING-STORAGE SECTION` は呼び出し間で値が保持される (静的) 動作を既定とし、
  `VALUE` 句による初期化タイミングを参照実装と一致させる。
- **FR-014 (L2)**: 複数コンパイル単位を 1 ソースファイルに含むバッチコンパイル
  (`END PROGRAM` 連結) をサポートする。

### 5.3 データ定義とメモリモデル

これは本プロジェクトの中核要件である。COBOL の意味論は「連続したバイト領域上のビュー」に
依存しており、Java のオブジェクトモデルへ素朴に写像すると互換性が破綻する。

- **FR-020 (L3)**: すべてのデータ項目は、連続したバイト列 (バイト配列) 上のオフセット・長さの
  ビューとして表現する。集団項目 (group item) は配下の基本項目 (elementary item) が占める
  バイト範囲そのものであり、集団項目への操作は英数字項目として無変換でバイト単位に作用する。
- **FR-021 (L3)**: `REDEFINES` は同一バイト範囲への別ビューとして実装し、
  一方への書き込みが他方から即座に観測されること。多段 REDEFINES を含む。
- **FR-022 (L3)**: レベル番号 01-49、66 (`RENAMES`)、77、88 (条件名) をサポートする。
  `RENAMES THRU` によるバイト範囲の再命名を正しく扱う。
- **FR-023 (L3)**: 境界調整 (`SYNCHRONIZED`) によるスリップバイト挿入を、参照実装と同一の
  位置・長さで再現する。集団項目内のオフセットに影響するため L3 必須とする。
- **FR-024 (L3)**: `OCCURS` による表、多次元 (7 次元まで)、`OCCURS DEPENDING ON` (ODO) による
  可変長項目を実装する。ODO 対象項目の長さ変化がレコード長・後続項目のオフセットへ与える影響、
  および ODO オブジェクトが範囲外の場合の挙動を参照実装に合わせる。
- **FR-025 (L3)**: `INDEXED BY` の索引名は、要素番号ではなく変位 (バイトオフセット) を保持する
  参照実装の内部表現に基づく挙動 (`SET`、相対添字、範囲外時の結果) を再現する。
- **FR-026 (L3)**: 部分参照 (reference modification) `項目(開始:長さ)` を実装する。
  `SSRANGE` 指定時は範囲チェックを行い、未指定時は参照実装と同様にチェックを行わない
  (未定義動作の再現方針は FR-201 に従う)。
- **FR-027 (L2)**: `LINKAGE SECTION` の項目は、呼び出し元から渡されたバイト領域への参照とし、
  未設定の項目へのアクセスは参照実装と同種の障害 (S0C4 相当) を発生させる。

### 5.4 PICTURE 句と USAGE

- **FR-030 (L3)**: PICTURE 文字 `A X 9 Z * + - CR DB . , / 0 B S V P $ (通貨) G N E` を
  参照実装と同一の規則で解釈し、桁数・バイト長・編集結果を一致させる。
- **FR-031 (L3)**: 以下の USAGE をサポートする。

  | USAGE | 表現 | 要件 |
  | --- | --- | --- |
  | `DISPLAY` | ゾーン10進 / 英数字 | 符号ニブル (正 `C`/`F`、負 `D`) の生成・受理規則を再現。`SIGN IS SEPARATE/LEADING/TRAILING` を含む |
  | `COMPUTATIONAL-3` / `PACKED-DECIMAL` | パック10進 | 1 バイト 2 桁、末尾ニブルが符号。偶数桁時の上位ゼロニブル、符号 `C`/`D`/`F` の扱いを再現 |
  | `COMPUTATIONAL` / `COMP` / `BINARY` | 2/4/8 バイト2進 | **ビッグエンディアン**。PICTURE 桁数による値域制限を `TRUNC` オプションに従って適用 |

- **FR-032 (L3)**: `COMP-1` / `COMP-2` について、`FLOAT-HEX` (既定, HFP) と `FLOAT-BINARY`
  (IEEE) の両方の表現を選択可能とし、既定は参照実装の既定に合わせる。
  HFP の丸め (切り捨て) 特性による演算結果の差異まで再現する。
- **FR-033 (L3)**: 符号なし項目への負値格納、無効なゾーン/パックデータの読み出しなど、

### 5.5 算術演算

- **FR-040 (L3)**: 10 進演算は 2 進浮動小数を経由せず、固定小数点 10 進として実行する。

  丸め・切り捨て位置を一致させる。
- **FR-041 (L3)**: `ARITH(COMPAT)` (最大 18 桁) と `ARITH(EXTEND)` (最大 31 桁) の
  両モードを実装し、中間結果の最大桁数と切り捨て位置の差を再現する。
- **FR-042 (L3)**: `ROUNDED` 句の丸めモード
  (`NEAREST-AWAY-FROM-ZERO` (既定)、`NEAREST-EVEN`、`NEAREST-TOWARD-ZERO`、`TOWARD-GREATER`、
  `TOWARD-LESSER`、`AWAY-FROM-ZERO`、`TRUNCATION`、`PROHIBITED`) をすべてサポートする。
- **FR-043 (L2)**: `ON SIZE ERROR` / `NOT ON SIZE ERROR` の発火条件 (ゼロ除算を含む) と、
  発火時に受取項目を変更しないセマンティクスを再現する。
- **FR-044 (L3)**: `COMPUTE`、`ADD`、`SUBTRACT`、`MULTIPLY`、`DIVIDE` (`REMAINDER` 付き含む)、
  `GIVING`、`CORRESPONDING` を実装する。
- **FR-045 (L3)**: `TRUNC(STD | OPT | BIN)` の 3 モードによる 2 進項目の切り捨て挙動の差を
  再現する。`TRUNC(OPT)` は最適化により参照実装で桁あふれが観測されない場合があるため、
  参照実装と同じ結果になるよう実装する。
- **FR-046 (L2)**: 比較 (数値比較・英数字比較・DBCS 比較・混在比較) の規則、および
  ゼロと符号の扱いを参照実装に合わせる。

#### 5.5.1 中間結果の桁数 (FR-040 の細目)

`COMPUTE` の式や `GIVING` を伴う算術文では、受取項目へ格納する前に**中間結果**が生じる。
中間結果の桁数は<b>翻訳時に決まる</b>。実行時に必要な精度を見てから決めるのではない。
除算は一般に有限桁で終わらないため、どこで打ち切るかを決めなければ結果が定まらないからである。

各被演算子に整数部の桁数 `i` と小数部の桁数 `d` を与える。データ項目は PICTURE 句から、
定数は書かれたとおりに数える。演算ごとの中間結果の桁数は次のとおりとする。

| 演算 | 中間結果の `i` | 中間結果の `d` |
| --- | --- | --- |
| `a + b` / `a - b` | `max(ia, ib) + 1` | `max(da, db)` |
| `a * b` | `ia + ib` | `da + db` |
| `a / b` | `ia + db` | `dmax` |
| `- a` (単項) | `ia` | `da` |

`dmax` は、**その文に現れるすべての被演算子と受取項目の小数部の桁数の最大値**である。
ただし<b>除数は数えない</b>。`ROUNDED` を指定した受取項目があれば `dmax` に 1 を加える
(丸めるには 1 桁余分に持っていなければならないためである)。

`dmax` を文全体から決めるのは参照実装の規則である。除算の商をその場の被演算子だけから
決めると、`COMPUTE A = B / C * D` のように後段で桁が伸びる式で精度が足りなくなる。

中間結果は<b>切り捨てる</b>。丸めるのは受取項目へ格納する最後の 1 回だけである
(`ROUNDED` の指定に従う)。

- **FR-047 (L3)**: 中間結果の総桁数 `i + d` は `ARITH(COMPAT)` で 30 桁、
  `ARITH(EXTEND)` で 32 桁を上限とする。超えた場合は<b>小数部から切り捨てて</b>上限に収める。
  整数部は切り捨てない。整数部を落とすと桁あふれが検出できなくなるためである。

### 5.6 文字コードと国際化

これは日本のホスト資産を扱ううえで極めて重要な要件である。

- **FR-050 (L3)**: 実行時の内部文字コードは **EBCDIC** を既定とする。文字列は Java の
  `String` (UTF-16) ではなくバイト列として保持し、必要時のみ変換する。
- **FR-051 (L3)**: 以下のコードページをサポートする。

  | コードページ | 用途 |

  | IBM-1047 | Latin-1 / Open Systems 用 EBCDIC |
  | IBM-037 | 米国・カナダ EBCDIC |
  | IBM-930 / IBM-5026 | 日本語 (カタカナ) 混在。SBCS はカタカナ |
  | IBM-939 / IBM-5035 | 日本語 (英小文字) 混在。SBCS は英小文字 |

## 6. 機能要件: ファイル入出力とデータセット

### 6.1 編成とアクセス

- **FR-100 (L3)**: 以下のファイル編成をサポートする。

  | 編成 | ホスト対応 | 要件 |

- **FR-107 (L2)**: `SAME AREA` / `SAME RECORD AREA`、`APPLY WRITE-ONLY`、
  `MULTIPLE FILE TAPE` を構文として受理し、意味的に安全な範囲で実装する。

### 6.2 データセットの物理表現

- **FR-110 (L3)**: **既定の格納形式は EBCDIC の生バイトとする。** ホストのデータセットを
  移行した際のバイト列を、変換せずそのままローカルファイルまたはオブジェクトストレージ上の
  ファイルとして保持する。RECFM (F/FB/V/VB/U)、LRECL、BLKSIZE、コードページの属性は、
  データ本体とは別のサイドカー・メタデータとして保持する。
  生バイトを既定とするのは、UTF-8 等へ変換して保存すると、往復変換での情報欠落、
  照合順序の不一致、パック10進などのバイナリ項目の破壊により L3 が原理的に成立しないためである。
- **FR-111 (L2)**: DD 割当単位で**変換アダプタ**を指定できること。外部システムとの連携ファイルや
  人間が直接参照するログのように、テキストとして扱うことに利点がある経路に限り、
  UTF-8 等への変換を選択できる。変換アダプタを適用した経路は L3 の対象外であることを
  実行時ログに記録する。
- **FR-112 (L2)**: データセットの物理格納先を差し替え可能なストレージ抽象層を設ける。
  最低限、ローカルファイルシステム実装を提供し、
  オブジェクトストレージ / RDB 実装を追加できる拡張点を定義する。
- **FR-113 (L2)**: 区分データセット (PDS/PDSE) をディレクトリとして写像し、
  メンバ名によるアクセスを可能にする (主に COPY ライブラリ、JCL、制御カード用途)。
- **FR-114 (L2)**: 世代データグループ (GDG) の相対世代 (`(0)`、`(+1)`、`(-1)`) を
  模した参照を提供する。
- **FR-115 (L2)**: レコードロック・共有オプション (VSAM SHAREOPTIONS 相当) を、
  同時実行時の整合性が保てる範囲で提供する。

### 6.3 ソート / マージ

- **FR-120 (L2)**: `SORT` / `MERGE` 文、`INPUT PROCEDURE` / `OUTPUT PROCEDURE`、
  `USING` / `GIVING`、`RELEASE` / `RETURN`、`DUPLICATES IN ORDER` をサポートする。
- **FR-121 (L3)**: ソートキーの比較は、キー項目の USAGE に応じたホストの照合規則
  (EBCDIC 照合順序、パック10進の符号込み比較等) に従う。
- **FR-122 (L2)**: メモリに収まらないデータ量に対して外部マージソートを行い、
  一時領域の場所とサイズを設定可能とする。

## 7. 機能要件: 実行環境とサブシステム連携

### 7.1 ジョブ実行 (バッチ)

- **FR-130 (L2)**: **内部ジョブモデル**を定義する。ジョブ、ステップ、プログラム、DD 割当、
  条件判定、復帰コードの伝播を表す、記述形式に依存しないモデルとする。
  ジョブの実行機構はこのモデルのみを解釈し、記述形式のパーサからは独立させる。
- **FR-131 (L2)**: 内部ジョブモデルの**フロントエンドとして JCL パーサ**を提供する。
  既存の JCL 資産を書き換えずに実行できることを目的とする。最小サポート範囲は
  `JOB`、`EXEC PGM=`、`PARM=`、`DD` (`DSN`、`DISP`、`SYSOUT`、`SYSIN` の `*` / `DATA`、
  `DUMMY`、`CONCATENATION`)、`COND` / `IF-THEN-ELSE-ENDIF` によるステップ制御、
  `PROC` / `INCLUDE` / シンボリックパラメータとする。
  JCL 全機能の再現は目標としないが、**未対応の JCL 構文は無視せず明示的にエラーとする**。
- **FR-132 (L2)**: 第 2 のフロントエンドとして、内部ジョブモデルを直接記述できる
  宣言的形式 (YAML 等) を提供する。新規に組むジョブや、本処理系自身のテスト記述に用いる。
  両フロントエンドは同一の内部モデルへ落ちるため、実行結果は一致しなければならない。
- **FR-133 (L2)**: DD 名から実ファイル・ストレージへの割当を、実行時設定
  (設定ファイルまたは環境変数) で行える。FR-111 の変換アダプタの指定もここで行う。
- **FR-134 (L2)**: `PARM=` の内容を、参照実装と同一の形式 (先頭 2 バイト長 + データ) で
  `PROCEDURE DIVISION USING` の引数として渡す。
- **FR-135 (L2)**: `SYSOUT` / `SYSPRINT` / `SYSIN` を `DISPLAY` / `ACCEPT` および
  ファイル I/O から利用可能にする。`DISPLAY UPON SYSPUNCH / CONSOLE` を含む。
- **FR-136 (L2)**: ステップの復帰コード (RC) を集約し、後続ステップの `COND` 判定および
  ジョブ全体の終了コードへ反映する。
- **FR-137 (L1)**: 代表的なユーティリティの互換実装を提供する:
  `IEBGENER`、`IEFBR14`、
  `IDCAMS` (`REPRO`、`DEFINE CLUSTER`、`DEFINE GDG`、`DELETE`、`LISTCAT` の主要機能)、
  `SORT` / `ICETOOL` (基本的な `SORT FIELDS`、`INCLUDE`/`OMIT`、`OUTREC`、`SUM`)、
  `IEBCOPY` (`COPY`、`SELECT`、`EXCLUDE`)、`IKJEFT01` (`LISTDS`)。

### 7.2 ランタイム (Language Environment 相当)

- **FR-140 (L2)**: LE 相当のランタイム基盤を提供し、以下を再現する。
  - プログラム開始・終了処理、ストレージ管理、条件処理 (condition handling)
  - `CEE3ABD` (ABEND 要求)、`CEEMOUT` (メッセージ出力)、`CEEGMT`/`CEELOCT` (時刻取得)、
    `CEE3PRM` (パラメータ取得) など、業務プログラムから直接呼ばれる頻度の高い
    LE コーラブルサービスの互換 API
  - ランタイムオプション (`TRAP`、`TERMTHDACT`、`STORAGE`、`RPTOPTS`、`ALL31`、`HEAP`) の
    主要なもの
- **FR-141 (L2)**: ABEND を再現する。少なくとも以下を、同じコードで発生させる。

  | コード | 契機 |
  | --- | --- |
  | S0C7 | 数値項目の不正データ (10 進演算例外) |
  | S0CB | ゼロ除算 (10 進除算例外) |
  | S0C4 | 保護例外 (未設定 LINKAGE 項目の参照等) |
  | S0C1 | 実行不可能命令 (未解決の動的 CALL 等) |
  | S806 | ロードモジュールが見つからない |
  | S013 / S001 / S037 | データセットのオープン・入出力エラー |
  | U1000 番台 | LE 検出条件 (`U4038` を含む) |

- **FR-142 (L2)**: ABEND 発生時に、参照実装に準じた診断出力 (CEEDUMP 相当) を生成する。
  ABEND コード、発生プログラム名、ステートメント番号、呼び出し履歴、
  主要データ項目のダンプを含む。
- **FR-143 (L2)**: `TERMTHDACT` 設定に応じたダンプ詳細度の切り替えを提供する。

### 7.3 データベース連携 (Db2)

- **FR-150 (L1)**: `EXEC SQL ... END-EXEC` を解析し、JDBC 呼び出しへ変換する SQL
  コプロセッサを提供する。
- **FR-151 (L2)**: `SQLCA` (`SQLCODE`、`SQLSTATE`、`SQLERRD`、`SQLWARN`) を正しく設定する。
  少なくとも `0`、`+100`、`-803`、`-911`、`-913`、`-805` 等、業務ロジックが分岐に使う
  主要 SQLCODE を、対応する JDBC 例外から適切に写像する。
- **FR-152 (L2)**: ホスト変数のバインド時に、COBOL のデータ型 (パック10進、ゾーン10進、
  可変長文字 `VARCHAR` 構造) と SQL 型の変換を、桁落ち・丸めなく行う。
- **FR-153 (L2)**: カーソル操作 (`DECLARE`、`OPEN`、`FETCH`、`CLOSE`、
  `WITH HOLD`、`FOR UPDATE`)、`INCLUDE SQLCA`/`INCLUDE メンバ`、
  動的 SQL (`PREPARE`/`EXECUTE`/`EXECUTE IMMEDIATE`/`DESCRIBE`) をサポートする。
- **FR-154 (L1)**: `COMMIT` / `ROLLBACK` を JTA またはコネクション単位のトランザクションへ写像する。
- **FR-155 (L1)**: 移行先 RDBMS (PostgreSQL 等) と Db2 の SQL 方言差を吸収する変換層を設けるが、
  完全な方言変換は本プロジェクトのスコープ外とし、差分は診断として報告する。

### 7.4 オンライン連携 (CICS / IMS)

- **FR-160 (L1)**: `EXEC CICS ... END-EXEC` を解析するトランスレータを提供する。
  第 1 段階の対象コマンドは以下とする。
  - プログラム制御: `LINK`、`XCTL`、`RETURN` (`TRANSID`、`COMMAREA`)、`LOAD`、`RELEASE`
  - 記憶域: `GETMAIN`、`FREEMAIN`、`ADDRESS`、`ASSIGN`
  - データ: `READ`、`WRITE`、`REWRITE`、`DELETE`、`STARTBR`/`READNEXT`/`ENDBR` (ファイル制御)
  - 一時記憶: `READQ TS`/`WRITEQ TS`/`DELETEQ TS`、`READQ TD`/`WRITEQ TD`
  - 端末: `SEND MAP` / `RECEIVE MAP` (BMS)、`SEND TEXT`
  - その他: `ABEND`、`HANDLE CONDITION` / `RESP` / `RESP2`、`SYNCPOINT` / `ROLLBACK`
- **FR-161 (L1)**: `EIB` (`EIBCALEN`、`EIBAID`、`EIBTRNID`、`EIBDATE`、`EIBTIME`、`EIBRESP` 等) を
  提供し、業務ロジックが参照する主要フィールドを正しく設定する。
- **FR-162 (L1)**: BMS マップ (BMS マクロ) を解析し、画面定義を構造化データへ変換する。
  3270 画面そのものの再現は必須とせず、フィールド単位のデータ入出力インタフェースを提供する。
- **FR-163 (L1)**: 疑似会話型トランザクションの状態保持 (COMMAREA / チャネル・コンテナ) を
  サポートする。
- **FR-164 (L1)**: IMS DL/I 呼び出し (`CBLTDLI` / `AIBTDLI`) のインタフェースを定義し、
  PCB マスク・SSA・状態コード (`GA`、`GB`、`GE`、`II` 等) を扱えるようにする。
  実際のデータベースへの写像は、差し替え可能なアダプタとして提供する。
  IMS 連携はフェーズ 4 の目標とし、初期リリースではインタフェース定義のみとする。

### 7.5 Java との相互運用

- **FR-170 (L2)**: コンパイル済み COBOL プログラムを、Java から型安全に呼び出せる API を提供する。
  引数はバイト配列ビューとして渡すほか、生成された Java レコード/クラスによる
  ラッパ (コピー句からの自動生成) を提供する。
- **FR-171 (L2)**: COBOL から Java クラスのメソッドを呼び出せる機構を提供する。
  参照実装のオブジェクト指向 COBOL 構文 (`INVOKE`、`CLASS-ID`、`METHOD-ID`、
  `REPOSITORY` の `CLASS ... IS "java.lang.String"` 等) との構文互換を目標とする。
- **FR-172 (L2)**: コピー句 (COPYBOOK) から Java のデータアクセスクラスを生成するツールを提供する。
  生成物は FR-020 のバイト列ビューを保ちつつ、`get`/`set` による型付きアクセスを提供する。
- **FR-173 (L1)**: Spring 等の DI コンテナ、およびサーブレット/REST フレームワークから
  COBOL プログラムを呼び出すためのアダプタ例を提供する。

## 8. 機能要件: コンパイラとツール

### 8.1 コンパイラ

- **FR-180**: コマンドラインコンパイラを提供する。入力は COBOL ソース、出力は JVM 上で
  実行可能な成果物 (クラスファイル/JAR) とする。
- **FR-181**: 参照実装の主要コンパイラオプションと同名・同義のオプションを受理する。
  少なくとも以下を実装する。

  | オプション | 影響 |
  | --- | --- |
  | `ARITH(COMPAT/EXTEND)` | 演算桁数 (FR-041) |
  | `TRUNC(STD/OPT/BIN)` | 2 進項目の切り捨て (FR-045)。`OPT` の扱いは FR-205 に従う |
  | `NUMPROC(PFD/NOPFD/MIG)` | 符号の正規化と妥当性検査 (FR-033) |
  | `NUMCHECK` | 数値妥当性の実行時検査 |
  | `SSRANGE` / `NOSSRANGE` | 添字・部分参照の範囲検査 |
  | `QUOTE` / `APOST` | 図形定数 `QUOTE` の値 |
  | `PGMNAME(COMPAT/LONGUPPER/LONGMIXED)` | プログラム名の扱い |
  | `CODEPAGE(nnnn)` | 実行時コードページ (FR-051) |
  | `NSYMBOL(NATIONAL/DBCS)` | `N` リテラルの解釈 |
  | `FLOAT(HEX/BINARY)` | 浮動小数の内部表現 (FR-032) |
  | `DYNAM` / `NODYNAM` | CALL の解決方式 |
  | `RENT` / `NORENT` | 再入可能性 |
  | `OPTIMIZE(0/1/2)` | 最適化レベル |
  | `SOURCE` / `MAP` / `LIST` / `XREF` / `OFFSET` | リスト出力 |
  | `TEST` | デバッグ情報の生成 |
  | `ZONEDATA` | ゾーン10進データの妥当性前提 |

  未実装のオプションは、無視せず「未対応」と診断する。
- **FR-182**: コンパイルリスト (ソースリスト、データマップ、相互参照リスト、
  診断メッセージ一覧) を出力する。データマップには各項目のオフセット・長さ・
  内部表現を含め、ホストのリストと突合可能にする。
- **FR-183**: 診断メッセージは、重大度 (I / W / E / S / U) と一意のメッセージ ID を持ち、
  該当行・桁を指す。日本語・英語のメッセージカタログを切り替え可能とする。
- **FR-184**: 分割コンパイルと、複数プログラムの一括ビルドをサポートする。
  Maven / Gradle プラグインを提供する。

### 8.2 移行診断ツール

- **FR-190**: ソース資産を静的解析し、移行リスクを報告するツールを提供する。報告項目:
  - 未対応構文・未対応コンパイラオプションの一覧と該当箇所
  - 互換性レベルが L1 以下となる機能の使用箇所
  - 環境依存 (ホスト固有の日付・時刻・データセット名・HLASM 呼び出し) の検出
  - コピー句・呼び出し関係のグラフ、デッドコード候補
- **FR-191**: 報告は機械可読形式 (JSON / SARIF) と人間可読形式 (HTML / Markdown) の
  双方で出力する。

### 8.3 デバッグとテスト支援

- **FR-192**: ソースレベルデバッグを可能にする。COBOL ソースの行番号でブレークポイントを設定し、
  データ項目の値を COBOL の表現 (編集後の見た目と 16 進ダンプの両方) で参照できること。
  JDWP による IDE 連携を目標とする。
- **FR-193**: `USE FOR DEBUGGING` および `WITH DEBUGGING MODE` によるデバッグ行の
  条件付き有効化をサポートする。
- **FR-194**: 実行トレース (実行された段落・文の系列、CALL 履歴) を出力できること。
- **FR-195**: 単体テスト支援機構を提供する。COBOL プログラムに対して入力データ (バイト列) を
  与え、出力を期待値と突合するテストランナーを提供する。
- **FR-196**: ホストと本処理系の出力を突合する比較ツール (EBCDIC 対応の差分ツール、
  レコード様式を考慮したバイナリ差分) を提供する。

## 9. 未定義動作・非決定性の扱い

「IBM ホストと互換」を追求する際、最も難しいのは仕様上「未定義」とされる領域である。
本プロジェクトでは以下の方針を採る。

- **FR-200**: 標準規格上は未定義でも、参照実装で**再現性のある**挙動を示すものは、
  その挙動を仕様とみなして再現する (例: 添字範囲外アクセス時に隣接領域を読む、
  初期化されていない `WORKING-STORAGE` の内容、`SEARCH ALL` の未ソート時の結果)。
- **FR-201**: 再現対象の未定義動作は、テストケースとして明示的に記録し、
  「意図された非互換」と「未検証」を区別できるようにする。
- **FR-202**: 再現が技術的に不可能または過大なコストとなる未定義動作は、
  第 11 章の制約事項に記載し、コンパイラの診断で検出可能にする。
- **FR-203**: 実装として安全側に倒す場合 (例: 実際のメモリ破壊を伴う動作) は、
  同等の観測結果を返しつつ、ランタイムオプションで「厳格モード (即時 ABEND)」と
  「互換モード (ホストの挙動を模倣)」を切り替え可能にする。
- **FR-205**: 参照実装の仕様書自身が「**結果は保証されない / 予測できない**」と明言している
  領域についても、FR-203 と同じ 2 モード方式を適用する。**既定は安全側**とし、
  定義された挙動を返したうえで警告を出す。互換モードでは参照実装の実装上の挙動を模倣する。
  代表例は以下。

  | 領域 | 既定 (安全側) | 互換モード |
  | --- | --- | --- |
  | `TRUNC(OPT)` | `TRUNC(STD)` と同じ切り捨てを行い、警告を出す | 切り捨てを省く挙動を模倣する |
  | `NUMPROC(PFD)` に不正な符号・数字が渡された場合 | 検査して ABEND (S0C7 相当) | 検査せず、そのままのバイト列で演算を継続する |
  | `SEARCH ALL` の対象表が未ソート | 検出して警告または ABEND | 2 分探索をそのまま実行し、不定の結果を返す |

  データが宣言どおりに収まっている限り両モードの結果は一致するため、
  既定を安全側に置くことによる実害は、元々未定義であったケースに限定される。
- **FR-206**: 互換モードで模倣する挙動には V2 の裏付けがないことをリリースノートに明記し、
  互換モードを有効にした実行では、その旨を実行時ログへ記録する。
- **FR-204**: 日付・時刻・乱数・ジョブ名など非決定的な値は、テスト時に固定できる
  注入機構を設ける (`CURRENT-DATE`、`ACCEPT ... FROM DATE/TIME`、`FUNCTION RANDOM` の種)。

## 10. 非機能要件

### 10.1 性能

- **NFR-001**: 数値演算・文字列処理を中心とする典型的なバッチ処理において、
  同世代のハードウェア資源あたりのスループットが、
  参照実装 (実機) と比較して**同等以上**であることを目標とする。
  ベンチマークセットを定義し、リリースごとに測定・公開する。
- **NFR-002**: パック10進・ゾーン10進の演算は、`java.math.BigDecimal` への変換を
  ホットパスで避け、バイト列上で直接演算する実装を優先する。
- **NFR-003**: 起動時間: 単純なバッチプログラムの JVM 起動を含む実行時間が 1 秒以内であること。
  AOT / CDS / GraalVM Native Image による短縮を検討する。
- **NFR-004**: 大量データ処理時に、レコード件数に比例したヒープ消費が発生しないこと
  (ストリーミング処理を基本とする)。
- **NFR-005**: 性能のためであっても、互換性を犠牲にする最適化は行わない。
  最適化により結果が変わりうる場合は、オプトインのオプションとする。

### 10.2 信頼性・可用性

- **NFR-010**: ランタイムの内部エラー (処理系のバグ) と、業務プログラムのエラーを
  明確に区別して報告する。前者は診断情報と再現手順を含むレポートを生成する。
- **NFR-011**: ファイル書き込み中の異常終了時に、データセットが中途半端な状態にならないよう、
  コミット境界を定義する。
- **NFR-012**: 同一入力に対して、実行環境 (OS、JVM ベンダ、CPU アーキテクチャ) が異なっても
  同一の出力を得られること (決定性)。特に浮動小数演算は `strictfp` 相当の厳密性を保証する。

### 10.3 移植性

- **NFR-020**: 対応 JVM は Java 21 (LTS) 以上とする。特定ベンダの JVM に依存しない。
- **NFR-021**: 対応 OS は Linux (x86-64 / aarch64)、Windows、macOS とする。
  改行コード・ファイルパス・文字コードの差異はランタイムが吸収する。
- **NFR-022**: コンテナ (OCI イメージ) での実行を標準的な配布形態のひとつとする。

### 10.4 保守性・拡張性

- **NFR-030**: 字句解析・構文解析・意味解析・中間表現・コード生成・ランタイムを
  明確に分離し、それぞれ独立してテスト可能とする。
- **NFR-031**: 方言 (IBM / Micro Focus / GnuCOBOL 等) を切り替え可能な構成とし、
  既定は IBM 方言とする。方言固有の処理は分離して実装する。
- **NFR-032**: 文字コード変換表、ファイルストレージ、サブシステム連携 (Db2/CICS/IMS) は
  差し替え可能なプラグイン境界とする。
- **NFR-033**: コード全体で、互換性に関わる判断には参照仕様の該当箇所または
  検証テストへの参照をコメントで残す。

### 10.5 テスト容易性と品質

テスト資産は以下の 3 層で構成する。3 層はそれぞれ異なる層の欠陥を捉えるため、相補的である。

- **NFR-040 (言語機能の網羅)**: NIST COBOL-85 検証テストスイート (CCVS85) を継続的に実行し、
  合格率を公開する。最終的に、対象モジュールの合格率 100% を目指す。
  Hercules オラクルでは到達できない「コンパイラが構文を受理し正しく実行するか」の層を担う。
- **NFR-041 (データ意味論の網羅)**: **合成テストジェネレータを自作する。**
  PICTURE 句 × USAGE × 演算・編集移送の組み合わせを機械的に列挙し、
  第 4.4 節のパイプラインで Hercules へ流し込んで結果バイト列を採取する。
  V2 に到達する主要な手段であり、組み合わせ爆発する領域を人力を超えた網羅性で押さえる。
  組み合わせ空間は次の方針で縮約する。
  - **境界値は全列挙する**: 桁数の境界 (1, 2, 15, 16, 18, 19, 31)、値の境界
    (0、±1、最大値、最大値 +1、小数点位置の両端)、符号ニブルの全パターン
    (`C` `D` `F` および不正値 `A` `B` `E`)、`P` による桁位置指定の両方向
  - **それ以外の軸は 2-way カバリングアレイ (pairwise) で縮約する**: USAGE ×
    演算種別 × 丸めモード × `ON SIZE ERROR` の有無 など。バグの大半は境界と
    2 要素の相互作用で顕在化するという経験則に依拠する
  - **打ち切り基準**: 主基準は pairwise カバレッジ 100% と境界値の全列挙完了。
    補助指標としてランタイムライブラリのコードカバレッジを用い、
    未到達分岐が残る場合は該当軸を 3-way へ引き上げる
- **NFR-042 (構文バリエーションの網羅)**: 公開されている OSS の COBOL ソース資産をコーパスとし、
  構文網羅率を測定する。実行はせず、コンパイル通過率と未対応構文の検出に用いる。
  R-7 (実装漏れによるコンパイル失敗) の早期検出を目的とする。
  **コーパス本体はリポジトリに同梱しない。** URL とコミットハッシュで固定した取得スクリプトを
  置き、取得時に SPDX 識別子をメタデータとして記録する。Apache-2.0 の成果物へ
  素性や条件の異なるソースを取り込まないための措置である。公開するのは網羅率の数値であり、
  コーパスそのものではない。
- **NFR-043**: すべてのテストケースに検証レベル (V0 / V1 / V2) を付与し、
  期待値の出所 (Hercules 採取 / 仕様書の該当箇所 / 推定) を記録する。
  リリースごとに検証レベル別の集計を公開し、互換性の裏付けの度合いを利用者が判断できるようにする。
- **NFR-044**: プロパティベーステストにより、10 進演算・編集・変換の性質
  (可換性、往復変換の一致、桁あふれ条件) を検証する。
- **NFR-045**: 主要コンポーネントの行カバレッジ 80% 以上、分岐カバレッジ 70% 以上。
- **NFR-046**: CI において、コンパイラのビルド・全テスト・ベンチマーク回帰検査を自動実行する。
  Hercules を用いた V2 期待値の採取は CI からは分離し、期待値の更新時のみ実行する。

### 10.6 セキュリティ

- **NFR-050**: COBOL の `CALL` によって任意のクラスがロードされうるため、
  ロード可能なプログラムの探索範囲を設定で制限できること。
- **NFR-051**: 動的 SQL を扱う際に、SQL インジェクションを誘発しない変換を行う

- **NFR-053**: 依存ライブラリの脆弱性を CI で継続的に検査する。

### 10.7 可観測性・運用

- **NFR-060**: ジョブ・ステップ・プログラム単位の実行ログ (開始/終了時刻、復帰コード、
  読み書きレコード件数、CPU 時間) を構造化ログとして出力する。
- **NFR-061**: OpenTelemetry によるメトリクス・トレースのエクスポートに対応する。
- **NFR-062**: 実行中のジョブの状態を確認できるインタフェースを提供する。

### 10.8 ドキュメント

- **NFR-070**: 言語リファレンス (対応状況を明記)、コンパイラオプション一覧、
  移行ガイド、非互換点一覧、運用ガイドを整備する。
- **NFR-071**: 非互換点一覧は、リリースごとに更新し、要件 ID と対応付ける。
- **NFR-072**: 主要ドキュメントは日本語と英語で提供する。

## 12. アーキテクチャ上の要求

設計の詳細は別文書に譲るが、要件を満たすうえで不可欠なアーキテクチャ上の制約を定める。

- **ARC-1**: フロントエンド (字句・構文・意味解析) と、バックエンド (コード生成) を分離し、
  中間表現 (IR) を介する。IR は COBOL の意味論 (バイト列上の操作) を保つ低水準表現とする。
- **ARC-2**: データ表現の実装は「バイト列 + ビュー」を基本とする (FR-020)。
  Java の `String` / `int` / `BigDecimal` への写像は、意味が完全に一致する場合の
  最適化としてのみ行う。
- **ARC-3**: 生成物は **ASM による JVM バイトコードの直接生成**とする。Java ソースを生成して
  `javac` に渡す方式は採らない。理由は、COBOL の `GO TO`、`PERFORM THRU` の範囲外脱出、
  `ALTER`、`DECLARATIVES` への制御移行がいずれも任意位置へのジャンプを要求するのに対し、
  **Java 言語には `goto` が存在しない**ためである。この方式ではステートマシン化が必須となり、
  性能・可読性・実装の素直さを同時に損なう。JVM バイトコードには `goto` があるため、
  直接生成のほうが COBOL の制御フローと構造的に整合する。
  デバッグ性は FR-192 のソースレベルデバッグと、生成バイトコードの逆アセンブル出力で担保する。
- **ARC-4**: ランタイムライブラリはコンパイラから独立したモジュールとし、
  生成コードが依存する API を安定させる。バージョン間の互換性ポリシーを定める。
- **ARC-5**: 文字コード変換、ファイルアクセス、サブシステム連携は、
  サービスプロバイダインタフェース (SPI) として定義する。
- **ARC-6**: 参照実装の挙動に関する判断は、コード中に散在させず、
  「方言定義 (dialect profile)」として一箇所に集約し、データ駆動で切り替え可能にする。
- **ARC-7**: **ランタイムライブラリ先行**。データ表現・10 進演算・編集移送・文字コード変換の
  意味論は、コード生成に一切依存しない「バイト列 in → バイト列 out」の純関数として
  ランタイムライブラリ側に閉じ込める。これにより、
  (a) Hercules から採取した V2 期待値をランタイムへ直接ぶつけて検証でき、
  (b) コード生成器の責務が制御フローと呼び出しの正しさだけに縮小し、
  (c) 障害発生時に「意味論のバグか、コード生成のバグか」を切り分けられる。
  ARC-3 で中間インタプリタによる自己相互検証を行わない選択をした以上、この分離は必須とする。
- **ARC-8**: 構文解析は**ハイブリッド方式**とする。手書きのプリプロセッサが文脈依存性を
  すべて吸収し、正規化済みトークン列を ANTLR4 の構文解析器へ渡す。
  - 手書き側の責務: カラム分解、継続行の空白補完 (FR-003)、`COPY` / `REPLACING` の擬似テキスト
    展開、`REPLACE`、コンパイラ指示文 (FR-092)、原典ソースへの行番号マッピング (FR-094)、
    および下記「島」の切り出し
  - ANTLR4 側の責務: 正規化済みトークン列に対する構文解析と構文木の構築
  - **島 (不透明トークン)**: 以下は 1 個の不透明トークンとして丸ごと切り出し、
    ANTLR4 には中身を見せない。それぞれ専用の小さなパーサで解析する。
    - `PICTURE` / `PIC` 句の文字列 — `PIC 99.99` の `.` が文末ピリオドと区別できないため、
      この問題をレキサから排除することが目的
    - `COPY` 文および `REPLACE` 文 (プリプロセッサ自身が消費する)
    - `EXEC SQL ... END-EXEC` (FR-150 の SQL コプロセッサへ渡す)
    - `EXEC CICS ... END-EXEC` (FR-160 のトランスレータへ渡す)
    - 継続行をまたぐ文字定数
- **ARC-9**: 実装言語は **Java 21 単一**とする。生成コードが依存するランタイムと処理系本体の
  言語を揃え、ARC-4 の API 安定性とデバッグ時の一貫性を確保する。

| R-9 | 互換モード (FR-205) で模倣する挙動に裏付けがない | 互換モードを信頼した移行で差異が出る | 既定を安全側に置き、互換モードは明示的な opt-in とする。裏付けがないことをリリースノートと実行時ログに記録する (FR-206) |

| # | 論点 | 決定 | 根拠 | 反映先 |
| --- | --- | --- | --- | --- |
| **D-1** | 期待値採取のオラクル | **Hercules のみを用いる。** z/OS 実機は利用しない | IBM は Hercules 上での z/OS の実行をライセンスしていないため、Enterprise COBOL 6.x のコンパイラ本体は入手できない。一方、Hercules は z/Architecture の命令を実装しており、L3 要件のうち命令の挙動に還元できる部分は実行検証できる | 1.4, 4.2, 4.3, G-2, R-1, R-1b |
