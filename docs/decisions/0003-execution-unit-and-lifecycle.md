# ADR-0003: Java からの連続呼び出しは CobolSession を実行単位とする

| 項目 | 内容 |
| --- | --- |
| 状態 | 採用 |

| 関連要件 | FR-014, FR-080, FR-083, FR-084, NFR-060, NFR-061 |
| 関連設計 | [設計 75](../design/75-java-interop.md) |

## 文脈

`ProgramContext` は、読み込んだ副プログラムとその `WORKING-STORAGE`、`EXTERNAL`、特殊レジスタ、
開いたファイル、コードページ、時計、入出力を持つ。これは単なる呼び出しオプションではなく、
COBOL の「実行単位」に相当する状態である。

Java API を `static call(name, byte[])` だけにすると、呼び出すたびに状態を捨てるか、JVM 全体で
共有するかのどちらかになる。前者は COBOL の連続呼び出しと `CANCEL` の意味を壊し、後者は
Web リクエストや並列ジョブのデータを混ぜる。

## 決定

Java ホストは不変でスレッド安全な `CobolRuntime` から `CobolSession` を開く。
`CobolRuntime` はカタログと既定設定だけを共有し、COBOL の可変状態はすべてセッションが所有する。
`CobolSession` の開始から `close` までを1実行単位とする。

Java から副プログラムとして呼ぶ `call` と、主プログラムとして起動する `runMain` を分ける。
呼び出しフレームは深さだけでなく起動種別を持つ。これにより最外フレームでも、`call` された
プログラムの `EXIT PROGRAM` は Java へ戻り、`runMain` の `EXIT PROGRAM` は何もしない。

同じセッションで同じプログラムを再度呼ぶと、前回の `WORKING-STORAGE` を引き継ぐ。
`session.cancel(programId)` 後の次の呼び出しでは初期像から作り直す。`EXTERNAL` と特殊レジスタは
セッション全体で共有する。終了時には未クローズのファイルを閉じ、セッションが所有する一時資源を
解放する。

セッションはスレッドセーフではなく、同時に1本のスレッドだけが使える。別スレッドからの
重複呼び出しは待たせず `ConcurrentSessionUseException` で失敗させる。同一スレッドで
COBOL→Java→COBOL と戻る再入呼び出しは許し、同じ呼び出しスタック、`EXTERNAL`、特殊レジスタを
引き継ぐ。並列実行はセッションを分ける。

Java アダプタのインスタンスもセッションが所有する。アプリケーション全体で共有したいサービスは
アダプタのコンストラクタへ注入できるが、COBOL のプログラム状態として扱う値を singleton に置かない。

`CobolSession` は `AutoCloseable` とし、公開 API は try-with-resources を標準とする。`close` 後の
呼び出しと `STOP RUN` 後の再利用は拒否する。

## 影響

- Web リクエスト、メッセージ、ジョブ等の境界をセッションへ対応付ければ状態が混ざらない。
- 1回だけ呼ぶ便宜 API は、内部でセッションを開いて閉じるため状態を引き継がないことを名前と
  文書で明示する。
- `ProgramContext` の `withXxx` が別インスタンスを返し、一部の内部状態だけを共有する現在の方式は、
  実行単位の境界が曖昧になる。セッション所有状態を明確にした設定ビルダーへ段階的に置き換える。
- 非同期 Java アダプタは呼び出し中に完了を待つ必要がある。呼び出し終了後に `DataView` へ
  書き戻す設計は許可しない。

## 却下した案

### すべての状態を JVM の singleton に置く

テナント、リクエスト、並列ジョブの状態が混ざり、試験も相互依存になるため採用しない。

### 呼び出しごとに必ず新しい ProgramContext を作る

簡単だが、`WORKING-STORAGE` の保持、`EXTERNAL`、`CANCEL`、呼び出しをまたぐ特殊レジスタを
再現できない。明示的な one-shot API の内部動作としてだけ認める。

### セッションの全メソッドを同期化する

誤った共有を隠して呼び出し順を非決定的にする。COBOL の実行自体は直列であるため、所有単位を
分けて重複使用を早く検出する。
