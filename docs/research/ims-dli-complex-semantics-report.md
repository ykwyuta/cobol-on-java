## 1. はじめに

COBOL プログラムから見た DL/I は、`CALL 'CBLTDLI' USING FUNC, PCB, IOAREA, SSA...` というサブルーチン呼び出しに過ぎない。

しかしその背後にある**実行時セマンティクス（状態遷移、暗黙のカーソル位置、キー順序規則）**は精緻である。COBOL 資産が依存してきたこれらの振る舞いを再現しないと、業務ロジックの判定（特に `STATUS-CODE` や探索ループ）が変わってしまう。

本書では実装時に必要となる中核仕様を整理する。

## 2. コマンドコード (Command Codes)

SSA には、セグメント名に続いて `*` と英字 1 文字を付与することで検索・更新の振る舞いを変える機能がある。

```
SSA 例: CUSTROOT*D(CUSTID  = 12345678)
                ^^
                コマンドコード (*D = Path Call)
```

| コード | 名称 | 理解している挙動 | 検証レベル | 実装 |
| :---: | :--- | :--- | :---: | :---: |
| **`D`** | Path Call | 階層の複数レベル（親と子）を 1 回のコールで連結して I/O 領域へ取得する。`ISRT` 時も 1 回で親子同時に挿入できる。 | V1 | MVP |
| **`F`** | First Occurrence | カレント位置にかかわらず、その親の配下の最初のセグメントから探索を開始する。 | V1 | MVP |
| **`L`** | Last Occurrence | 条件に合致する兄弟セグメントのうち最後のものを取得する。 | V1 | MVP |
| **`C`** | Concatenated Key | 連結キー（ルートからのキーの連結）でセグメントを指定する。**実資産で頻出するが、改訂前の本書から漏れていた。** | V1 | MVP |
| **`N`** | Path Replace Suppress | `D` で複数レベルを取得した後の `REPL` で、特定レベルの更新を抑止する。 | V1 | 第 2 増分 |
| **`P`** | Set Parentage | 途中の親セグメントの SSA に指定することで、そのレベルを `GNP` の親として固定する。 | V1 | 第 2 増分 |
| **`-`** | Null | コマンドコードの位置を埋める。効果を持たない。 | V1 | 第 2 増分 |
| **`U` / `V`** | — | **役割が確定していない。** | **V0** | **見送り** |
| **`Q` / `O`** | — | 未調査。 | **V0** | 見送り |

### 2.1 `*U` / `*V` について（改訂前の記述は誤っていた可能性が高い）

改訂前の本書は `U` / `V` を「探索が失敗した場合（`GE`）に失敗前のカレント位置を厳格に保護・維持する」と説明していた。しかし `U` / `V` は、**探索中にそのレベル（`V` ではそのレベルと上位すべて）の位置を動かさない**ための指定であって、`GE` からの復帰機構ではないと思われる。

役割が確定していないので**実装しない**。公開仕様で確認するまで見送る ([P-100](../decisions/provisional.md))。

> **設計判断**: `D`（Path Call）、`F`（First）、`C`（連結キー）は実務 COBOL 資産で頻出するため、
> 第 1 増分で対応する。役割が未確定のものは実装しない。

## 3. SSA の文法

改訂前の本書は `SEGNAME*C(FIELD  = VALUE)` の 1 形しか想定していなかった。実資産には次の形がある。`SsaParser` はこれらを受ける。

```
ssa            ::= seg-name [ command-codes ] [ qualification ]
seg-name       ::= 8 バイト（右空白詰め）
command-codes  ::= '*' code+                       ; 例: *D, *DF, *C
qualification  ::= '(' condition ( connector condition )* ')'
condition      ::= field-name rel-op value
field-name     ::= 8 バイト（右空白詰め）
rel-op         ::= '=' | 'EQ' | '>' | 'GT' | '<' | 'LT'
                 | '>=' | 'GE' | '<=' | 'LE' | '!=' | 'NE'
connector      ::= '*' | '&'        ; AND
                 | '|'              ; OR
                 | '#'              ; 独立 AND
```

- **無限定 SSA**（セグメント名のみ、修飾なし）は `GN` の最頻形である。
- **レベルごとの複数 SSA** を 1 回のコールに並べられる（親に 1 つ、子に 1 つ）。
- 比較は**セグメント内の生バイトに対して行う**。したがってパック 10 進やバイナリのフィールドに対する `>` / `<` の意味は、表示形式の項目と同じにはならない。この点は未突合である。

**対応しない形は `AJ`（SSA 構文エラー）で誤魔化さない。**`AJ` は「SSA の書き方が間違っている」という意味であり、「処理系が対応していない」とは別である。後者は診断として区別して出す。

## 4. 親境界（Parentage）と `GNP`

`GNP` (Get Next in Parent) は「現在の親」が誰であるかに依存する。

```
       [ROOT: 顧客 10001]  <--- (1) GU 発行でここが Parentage になる
           |
           +-- [CHILD: 注文 A]  <--- (2) GNP で取得 (Parentage はルートのまま)
           |       +-- [GRANDCHILD: 明細 1]
           |       +-- [GRANDCHILD: 明細 2]
           |
           +-- [CHILD: 注文 B]  <--- (3) GNP で取得
```

### 4.1 確立と失効について理解していること（**すべて未突合**）

| 規則 | 検証レベル |
| --- | :---: |
| `GU` / `GN` の成功時、取得したセグメント（または `*P` を指定したレベル）が Parentage になる | V1 |
| `GNP` はセグメントを取得しても Parentage を前進させない | V1 |
| 別の `GU` / `GN` を呼ぶと Parentage が上書きされる | V1 |
| 親境界が確立していない状態で `GNP` を呼ぶと `GP` が返る | V1 |
| `GNP` が `GE` を返した後の振る舞い | **V0。下記参照** |
| `ISRT` / `DLET` の失敗時の親境界 | **V0。下記参照** |

改訂前の本書は「`GNP` で `GE` が返却された瞬間に親境界が消滅し、以降の `GNP` は直ちに `GE` となる」「`ISRT` / `DLET` が失敗したとき親境界がリセットされる」と断定していた。**どちらも出典が無い。**

前者について、「位置が親の従属セグメントの末尾へ移る」のと「親境界そのものが失われる」のは別の事象であり、後続で別の SSA を伴う `GNP` を発行したときに差が観測されうる。後者について、失敗の種類ごとに位置の扱いが異なる可能性がある。

**確認できるまで、この 2 つの規則に依存する実装を書かない** ([P-100](../decisions/provisional.md))。

### 4.2 PCB 状態管理オブジェクトの設計

```java
public class PcbInternalState {
    private String currentDbdName;
    private String currentHierarchyPath;    // 現在のカーソル位置
    private String establishedParentPath;    // 確立された親のパス (Parentage)
    private int establishedParentLevel;      // 親の階層レベル (1=ROOT, 2=CHILD...)
    private boolean parentageValid;          // 親境界が有効かどうか
    private byte[] lastRootKey;              // 現在のルートキー
}
```

## 5. 重複キーとキーなしセグメントの挿入規則 (`RULES`)

DBD において、キー項目がユニークでないセグメント、またはキー項目自体が存在しないセグメントの挿入順序は、DBD の `RULES=` パラメータで制御される。

| `RULES` 指定 | 意味 | RDB 上での採番方式 |
| :--- | :--- | :--- |
| **`RULES=(FIRST)`** | 同一キーの兄弟群の先頭に挿入する。 | 既存の最小シーケンス番号より小さい番号を採番する。**ギャップが尽きたら部分木を再採番する。** |
| **`RULES=(LAST)`** | 同一キーの兄弟群の末尾に追加する。 | 末尾のシーケンス番号の次を採番する。 |
| **`RULES=(HERE)`** | 直前のカーソル位置の直前／直後に挿入する。 | カレントの直後となるギャップ値を採番する。 |

> **改訂前にあった「小数点採番」は禁止する。**
> 改訂前は `RULES=(FIRST)` の回避策として「小数点・ギャップ採番」を挙げていたが、
> **これは先行順走査を壊す。**`.` (0x2E) は `/` (0x2F) より小さいため、`/001/01-000100.5` が
> `/001/01-000100/01-000100`（自分の子）より先に並び、`GN` が孫より先に兄弟を返す。
> 実測は [P-101](../decisions/provisional.md) に記録した。
>
> 各段は**固定幅・固定文字集合（数字と `-` のみ）**とし、ギャップ枯渇時は部分木を再採番する。
> `HIERARCHY_PATH` は主キーかつ全子孫の `PARENT_PATH` に埋め込まれているため、
> 再採番は部分木全体の書き換えになる。刻み幅とコストは実測して決める。

## 6. 複数 PCB による並行カーソル

COBOL プログラムの `PROCEDURE DIVISION USING ...` には複数の DB PCB を渡せる。

```cobol
PROCEDURE DIVISION USING IO-PCB, CUST-PCB, ORDER-PCB.
```

1. **別 DBD へのアクセス**: `CUST-PCB` は顧客 DB、`ORDER-PCB` は注文 DB を指す。
2. **同一 DBD に対する複数 PCB（マルチポジショニング）**: 2 つの PCB が同一 DBD を別々のカレント位置で走査する。

> **設計方針**: カレント位置や Parentage の状態は、ランタイムのグローバル変数ではなく、
> **引数として渡された各 `DB-PCB` のインスタンスごとに独立した `PcbInternalState`** として保持する。

## 7. `CHKP` の意味論

**`CHKP` はコミットだけではない。データベースの位置を破棄する。**

`GN` ループの途中で `CHKP` を打つバッチは、`CHKP` の後に `GU` で位置を取り直さなければならない。位置破棄を再現しないと、`CHKP` を挟んだ `GN` ループは実機と違う結果を返す（実機では止まるはずのループが動き続ける、逆もある）。改訂前の設計はこれを「JDBC コミットとの同期」としか書いていなかった。

- **basic `CHKP`**: コミット + 全 DB PCB の位置破棄。第 1 増分で対応する。
- **symbolic `CHKP`**（ユーザ領域の退避）と **`XRST`**（再始動）: **L0（未対応）**。呼び出しを検出したら診断を出す。GSAM とセットで別途設計する ([P-110](../decisions/provisional.md))。

**IMS バッチ移行で最も要求される再実行機能がここに集中している。**

## 8. 可変長セグメント

可変長セグメントは 2 バイトの長さフィールド (`LL`) を持つ。非正規化格納を選んだ理由の 1 つが ODO であるにもかかわらず、改訂前はこの表現が定義されていなかった。

- ストレージ上、セグメント本体と現在長を分けて保持する（[設計 78](../design/78-ims-subsystem.md) §3.6）。
- `REPL` による長さ変更を許す。
- `BYTES=(max,min)` の範囲検査を行う。
- `*D` パス呼出しで複数レベルを連結する際は、各レベルの現在長で連結する。

## 9. ステータスコード

COBOL プログラムは `CALL 'CBLTDLI'` 直後に 2 文字のコードで分岐する。**FR-164 は `GA`、`GB`、`GE`、`II` を例示しているが、改訂前の本書の表には `GA` が無かった。**

| コード | 意味 | 発生条件 | 検証 | 実装 |
| :---: | :--- | :--- | :---: | :---: |
| `'  '` | 正常終了 | 要求が正常に処理された | V1 | MVP |
| **`GA`** | 上位レベルへ移動 | **無限定 `GN` で階層のより上位レベルのセグメントへ移った** | V1 | **MVP** |
| **`GK`** | 別セグメントタイプ | **無限定 `GN` で同一レベルの別のセグメントタイプへ移った** | V1 | **MVP** |
| `GE` | 該当なし | 条件に合うセグメントが存在しない。`GNP` で親の範囲を越えた | V1 | MVP |
| `GB` | データベースの終端 | `GN` のループ終了条件 | V1 | MVP |
| **`GP`** | 親境界なし | **親境界が確立していない状態で `GNP` を呼んだ** | V1 | **MVP** |
| `II` | 重複挿入 | `UNIQUE` キーで既存のキー値を `ISRT` した | V1 | MVP |
| `DJ` | Hold 無しの更新 | 直前に Get Hold を呼ばずに `DLET` / `REPL` を呼んだ | V1 | MVP |
| `DA` | キー項目の変更 | `REPL` でシーケンスフィールドを書き換えた | V1 | MVP |
| **`AM`** | `PROCOPT` 違反 | **`PROCOPT` が許さない操作を発行した** | V1 | **MVP** |
| `AD` | 不正な機能コード | ファンクションコードが不正 | V1 | MVP |
| `AJ` | SSA 構文エラー | 括弧が閉じていない、演算子が不正など | V1 | MVP |
| `AK` | フィールド名未定義 | SSA のフィールド名が DBD に存在しない | V1 | MVP |
| `AI` | 入出力エラー | データセットのオープン・入出力エラー | V1 | 第 2 増分 |
| `QC` | キューが空 (TM) | メッセージキューが空になった | V1 | MVP |

**`GA` / `GK` は、無限定 `GN` で木を舐めるプログラムがセグメント種別の切り替わりを検出するために使う中核コードである。**返さないとループの制御が変わる。`GP` は §4 の親境界設計と直結する。`AM` は `PROCOPT` を扱う以上セットで必要になる。

各コードの発生条件は公開仕様と条項単位で突き合わせていない ([P-100](../decisions/provisional.md))。

## 10. 本書が扱わないもの

次は **L0（未対応）** とし、DBD / PSB のロード時に検出して診断を出す（[設計 78](../design/78-ims-subsystem.md) §1.1、[P-103](../decisions/provisional.md)）。

- **二次索引 (`PROCSEQ=`)**: 別のフィールドで階層順序そのものを差し替える。本書と RDB 設計が置く「階層順序は 1 つ」という前提を壊す。
- **論理関係 (`LCHILD` / 論理親子 / 連結セグメント)**: データが木でなく網になる。
- **GSAM**、**Fast Path (DEDB / MSDB)**。
- **HDAM / PHDAM のルート走査順序**: ランダマイザを再現できない ([P-102](../decisions/provisional.md))。

### 振る舞いの差が出るテストを書く

CLAUDE.md 増分の型 4 に従い、次のような「差が出る」テストを増分ごとに用意する。

- `CHKP` を挟んだ `GN` ループが、位置破棄によって実機同様に振る舞う
- `ISRT` の直後の `GN` が、挿入したセグメントを見る
- 無限定 `GN` が階層レベルの変化で `GA` / `GK` を返し分ける
- 親境界が無い状態の `GNP` が `GP` を返す
- `PROCOPT` が許さない操作が `AM` を返す
