# 設計: 日本語の検証 (オラクルが無いところをどう固定するか)

日本語には**外の基準が無い**。Hercules が動かす MVS 3.8j の世代に日本語コードページは
存在せず (要件定義書 4.3 節)、CCVS85 にも日本語の試験は 1 本も無い。
CLAUDE.md の増分の型は「1. 測る」から始まるが、**ここは 1 段目が回らない**。

それでも日本語は成立しなければならない。この文書は、測れないところで何を根拠に
何を固定したかを書く。

---

## 1. 測れないものを測ったことにしない

やってはいけないことが 2 つある。

1. **参照実装の値を推測して期待値に書く。** 書いた瞬間にそれは「自分で書いた規則」に
   なる。CLAUDE.md 第 3 節のとおり、自分で書いた規則は自分のテストでは破れない。
2. **日本語だけ検査を持たないまま置く。** 資産を流すまで壊れていることが分からない。

抜け道は 1 つある。**期待値を参照実装からではなく、入力そのものから導く**ことである。

## 2. 根拠は要件 FR-050 である

要件 FR-050 は、文字データを Java の `String` (UTF-16) ではなく
**バイト列として保持する**と決めている。これは測って確かめる振る舞いではなく、
**処理系の作りそのもの**である。`CodePage` の Javadoc にも書いてある。

作りがそのとおりなら、文字の意味を見ない演算は**バイトに対して透明**でなければ
ならない。透明性は入力と出力を見比べれば判定できる。参照実装は要らない。

したがって固定するのは次の 1 つである。

> **処理系は、渡されていないバイトを増やさない。渡されたバイトを減らさない。置き換えない。**

これが「文字が化けない」の定義である。

## 3. 「化けない」に含めないこと

`PIC X(5)` に全角 4 文字 (IBM-930 で 10 バイト) を転記すれば 5 バイト目で切れ、
シフトインが落ちて組が開いたままになる。**これは化けたのではない。**
ホストの `PIC X` も同じところで切れる。桁数を決めたのは資産であり、処理系が
繕えば実機と違う結果になる。

同じ理由で、次も処理系の失敗ではない。

| 現象 | なぜ処理系の失敗ではないか |
| --- | --- |
| `PIC X` の切り口が全角の途中に来る | ホストも同じ位置で切る。繕うほうが実機と食い違う |
| `INSPECT` の 1 バイト模様が全角の後続バイトに当たる | ホストの `INSPECT` もバイトで走査する |
| 組の開いたバイト列を `DISPLAY` すると読めない | 壊れた値でも見せないと調べる手段が消える |

**処理系の責任は、自分でバイトを作り変えないことまでである。**
切れた位置まで実機と同じであることは、ここでは言っていない。言うには実機が要る。

## 4. 既存のテストのうち、日本語でも成立すべきもの

日本語版は既存のテストを**書き替えていない**。同じ演算を検体だけ替えて呼ぶ形で足した。

| 既存のテスト | 見ている演算 | 日本語で成立すべきか | 日本語版 |
| --- | --- | --- | --- |
| `AlphanumericEditorTest` / 転記の検査 | `PIC X` への転記、埋め草、切り詰め、右詰め | **する** (バイト透明) | `JapaneseByteTransparencyTest` 転記の節 |
| `DataViewTest` | 部分参照、記憶域の出し入れ | **する** (バイト位置) | 同 部分参照の節 |
| `StringVerbTest` | `STRING DELIMITED BY SIZE` / 定数 / `POINTER` | **する** | 同 連結の節 |
| `UnstringVerbTest` | `UNSTRING` の区切りと受取欄 | **する** | 同 分解の節 |
| `InspectTest` / `InspectScanTest` | `TALLYING` / `REPLACING` | **する** | 同 走査の節 |
| `CompareTest` (英数字比較) | EBCDIC 照合順序 | **する** (バイト値の順) | 同 比較の節 |
| `SequentialDataSetTest` | 固定長レコードの切り出し | **する** | 同 ファイル入出力の節 |
| `RecordFramingTest` | レコードの枠 | **する** | 同上 (順編成で代表させた) |
| `DisplayGenerationTest` | `DISPLAY` の出力 | **する** (復号の経路) | `JapaneseGenerationTest` |
| `HexadecimalLiteralTest` | `X'..'` 定数 | **する** (日本語を書ける唯一の口) | 同 |
| `CodePageTest` | 符号化・復号・照合 | **する** | `JapaneseCodePageTest` |
| `ClassConditionTest` | `ALPHABETIC` / `NUMERIC` | **しない** | 後述 |
| `NumericEditorTest` / 算術一式 | 数値演算 | **しない** (数字は EBCDIC 不変部分) | 不要 |
| `IntrinsicFunctionTest` の `UPPER-CASE` / `LOWER-CASE` | 大小変換 | **しない** | 後述 |

### 成立しないと分かっているもの

| 演算 | なぜ成立しないか |
| --- | --- |
| 級条件 (`ALPHABETIC` / `NUMERIC`) | `ClassTest` が 1 バイトずつ復号する。IBM-930 で `"日本"` は `?a?e?` に崩れる。混在データに級条件を書くこと自体が規格の範囲外だが、**崩れ方が診断されない**のは直すべきである |
| `UPPER-CASE` / `LOWER-CASE` | 全角の扱いを決めていない |
| `PIC G` / DBCS の `PIC N` (`USAGE DISPLAY-1`、`NSYMBOL(DBCS)`) | 未実装。`DataDivisionBuilder` と `OptionSupport` が診断で断る (P-006) |
| 国字 (`PIC N`) の `STRING` / `INSPECT` / `ACCEPT` / 部分参照ほか | 国字を扱うのは `MOVE` / `DISPLAY` / `INITIALIZE` / `CALL` / 関係条件 / `NATIONAL-OF` / `DISPLAY-OF` だけである。ほかは `NationalGuard` が断る |

**断っているものは検査しない。**断れていることだけを検査する。

## 5. 日本語を原文に書ける口は 16 進定数と国字定数である

**2026-09-24 の追記**: 国字 (`PIC N`、`USAGE NATIONAL`) を実装した。国字定数 `N'山田'` は
原文の文字を**コードページを経由せずに** UTF-16 にするので、IBM-1047 のままでも日本語を
書ける。英数字の項目へ日本語を入れるには `FUNCTION DISPLAY-OF(N'山田', 939)` のように
CCSID を指定して直す。1390 / 1399 は JDK に無いので断る (P-002)。以下はこの追記より前の
記述である。


翻訳時のコードページは処理系のどこでも `CodePages.DEFAULT` (IBM-1047) に固定されて
おり、`CODEPAGE` オプションは無い (暫定判断 P-177)。IBM-1047 は日本語を持たないので、
原文に `VALUE '山田太郎'` と書くことはできない。

```cobol
      * いまは書けない。診断になる
       01 WS-NAME PIC X(10) VALUE '山田太郎'.

      * いま書ける。16 進定数はコードページを経由しない
       01 WS-NAME PIC X(10) VALUE X'0E4565456345AB456E0F'.
```

実行時のコードページは `ProgramContext.withCodePage` で差し替えられ、`DISPLAY` は
これを見る。だから**ファイル・`CALL` の引数・16 進定数からバイトとして入った日本語は、
いまでも端から端まで通る**。`JapaneseGenerationTest` がそれを固定している。

### 生成コードが IBM-1047 を焼き込んでいても日本語が狂わない理由

`ProgramGenerator.loadCodePage` は `CodePages.DEFAULT` を定数として埋め込む。
これが日本語の邪魔にならないのは、生成コードがコードページから取るものが
**EBCDIC の不変部分に限られている**からである。

| 生成コードが使うもの | IBM-1047 | IBM-930 | IBM-939 |
| --- | --- | --- | --- |
| 空白 (埋め草) | `X'40'` | `X'40'` | `X'40'` |
| 数字 `0`〜`9` | `X'F0'`〜`X'F9'` | 同じ | 同じ |
| 英大文字 `A`〜`Z` | `X'C1'`〜`X'E9'` | 同じ | 同じ |
| 照合順序 | バイト値の順 | 同じ | 同じ |

`JapaneseCodePageTest` がこの表を検査にしてある。**ここが崩れたら、焼き込みは
安全でなくなる。**そのときは `CODEPAGE` オプション (P-177) が先に要る。

## 6. 黙って化けていたもの — 直した

`CodePage.encode` は素の `String.getBytes(Charset)` だった。JDK の既定は
**表せない文字を置換文字へ倒す**ことである。

```
IBM-1047 で "山田太郎" を符号化 → X'3F3F3F3F' (EBCDIC の SUB)
```

`VALUE '山田太郎'` と書いた原文は、**診断も警告もなく翻訳を通り、実行も成功し、
`DISPLAY` は空行を出していた**。書いた 4 文字が消えたことに気付ける場所が
どこにも無かった。

`CodePages.forName` は未対応のコードページを `UnsupportedCharsetException` で断って
いた。符号化の側だけが黙って倒れていた。**断る側に揃えた。**

```
MAIN.cbl:5:20: character '山' (U+5C71) cannot be represented in IBM-1047
```

CLAUDE.md の「近い値を黙って返すくらいなら、書けないと断る」は、翻訳の拒否だけの
話ではなかった。**データの変換にも同じことが言える。**

## 7. この検査が言っていないこと

| 言っていないこと | 解消条件 |
| --- | --- |
| JDK の `x-IBM930` / `x-IBM939` の変換表が IBM CDRA と一致すること | P-012。CDRA の表と全コードポイントで突き合わせる |
| IBM-5026 / 5035 / 1390 / 1399 | P-002。登録すらしていない |
| 切れた位置・シフトコードの付け方が実機と同じであること | 実機かそれに代わるオラクルが要る |
| `PIC N` / `NATIONAL` の振る舞いが実機と同じであること | 国字は実装した (2026-09-24)。`NATIONAL-OF` の変換表は P-012、DBCS の `PIC N` と `PIC G` は P-006 で断っている。z/OS probe の `CBLCP` で実機の値と比べる |
| 日本語を含む原文の桁の数え方 | 原文は UTF-8 で読み、`SourceLine` は Java の `char` で 72 桁を数える。実機は**バイト**で数えるので、日本語を含む行は桁位置がずれる。P-177 で翻訳時のコードページを選べるようにするとき、同時に決める |
| 3270 / BMS の全角の cell 幅と SO / SI | 設計 81 章と ADR-0010 に未検証として挙げてある。`BmsInputDecoder` は 1 文字 1 バイトでない入力を断る |

### 符号化を厳しくした代償

`CodePage.encode` は `String.getBytes` から `CharsetEncoder` を組み立てる形になった。
1 回あたり 50ns から 60ns へ伸びる (IBM-1047、24 文字、100 万回の平均)。
`encode` が呼ばれるのは取引ごと・SQL 呼び出しごとであってバイトごとではないので、
符号化器を使い回す作りにはしていない。**測ってから要るかどうかを決める。**

`JapaneseCodePageTest` のうち**絶対値を見ているのは 1 本だけ**
(`fixtureBytesMatchTheJdkTable`) であり、JDK の表が変わったことに気付くための印として
置いてある。「実機がこうである」とは言っていない。そう読めるように検体
(`JapaneseFixtures`) にも印を付けてある。

## 8. 次に測れるようになったとき

CDRA の変換表を入れれば (P-002 の解消条件)、**変換表そのものが外の基準になる**。
Hercules のような実行によるオラクルではないが、自分で書いた値ではない。
そのとき、この文書の第 7 節の 1 行目が消える。

それまでは、ここに書いた**バイト透明性だけ**が日本語の裏付けである。
数は少ないが、**何を根拠にしているかは書いてある**。
