# 設計 27: HLASM の組み立てと実行

## 1. 位置づけ

[方式検討レポート](../research/hlasm-support-and-execution-requirements.md) で出した答えは
「骨格は PL/I と同じでよいが、部品が 2 つ足りない」であった。本書はその実装を決める。

| レポートの結論 | この設計での扱い |
| --- | --- |
| 薄い殻 + `CobolProgram` ABI はそのまま使える | 増分 1 後半。`cobol.generated.XXX` として、COBOL・PL/I と同じ名前空間に着地する (P-182) |
| 意味論はランタイムが持つ | 命令インタプリタが持つ。生成クラスは原文を渡すだけ |
| 足りない部品 1: レジスタと線形アドレス空間 | 増分 1 後半。`Storage` / `DataView` の下に敷く |
| 足りない部品 2: マクロと条件付きアセンブリ | 増分 2。ソース内マクロ、ライブラリマクロと基本的な条件付きアセンブリを実装。式・属性の全範囲は未対応 |
| 外の基準は Hercules | 増分 1 の時点から、組み立ての突き合わせに使う |

## 2. 層

```text
[ HLASM の原文 (.asm) ]
          |
          v  HlasmReader     固定形式 → 文の並び
          |
          v  Assembler       2 周。所在カウンタと記号 → 機械語
          |
   [ ObjectModule ]          節の先頭からの変位で持つ。番地は載せる側が決める
          |
          +---------------------------+
          |                           |
          v  (増分 1 後半)             v  (増分 0)
  命令インタプリタ               組み立ての突き合わせ
  + 線形アドレス空間              - PoP から作った期待値
  + 16 本の汎用レジスタ            - cobol-oracle の Insn (Hercules で裏づけ済み)
          |
          v
  CobolProgram ABI → 既存のプログラム解決・JCL・CICS / IMS
```

## 3. 測る対象は 2 つある

COBOL と PL/I では「翻訳できたか」「実行結果が合うか」の 2 つだった。HLASM では 2 段になる。

| 段 | 測るもの | 基準 |
| --- | --- | --- |
| 1. 組み立て | 原文 → 機械語と変位 | Principles of Operation の命令形式。`cobol-oracle` の `Insn` |
| 2. 実行 | その機械語を動かした結果 | Hercules |

**この 2 つを同じ数に混ぜない。**混ぜると次の形で測定が嘘をつく。

> 自分のアセンブラが誤った機械語を作ると、Hercules も自分のインタプリタも<b>同じ誤った機械語</b>を
> 実行する。結果は一致し、測定は緑になる。しかし原文の意味は再現できていない。

CLAUDE.md §6 は「検査の道具が、処理系の失敗を作ってはならない」と言う。ここはその裏返しで、
**道具が処理系の成功を作ってしまう**形である。だから状態の数え方に `WRONG_OBJECT` を置き、
`WRONG_OUTPUT` と区別する。

`InsnAgreementTest` が第 1 段の最初の基準である。`Insn` は Hercules へ流す命令列を組むために
別に書かれたもので、その出力で実行した結果は実際に Hercules と突き合わせ済みである
(暫定判断 P-001 のゼロ結果の符号など)。2 つの表が食い違えば、どちらかが誤っていると分かる。

## 4. 組み立て

### 4.1 2 周する理由

1 周目で所在カウンタを進めて記号の値と長さ属性を決め、2 周目でバイト列を作る。

`USING` は 1 周目では<b>辿らない</b>。所在カウンタを動かさないからであり、辿ると
「まだ定義されていない `DSECT` を先に `USING` する」という普通の書き方が前方参照で落ちる。

リテラル (`=F'7'`) だけは 1 周目に<b>字面から</b>拾う。拾わないとプールの大きさが 1 周目に
決まらず、プールより後ろの番地が全部ずれる。

### 4.2 番地の解決

`USING` は<b>翻訳時の状態</b>である。実行時にあるのはレジスタの値だけで、どのレジスタが
どこを指しているという情報は機械語のどこにも残らない。だから 2 周目でも同じ順に辿り直す。

届く `USING` が 2 つ以上あれば変位の小さいほうを選び、同じなら番号の大きいレジスタを選ぶ。
届くものが無ければ<b>断る</b>。ここを黙って 0 番 (ベースなし) に倒すと、組み立ては通って
実行時に番地 0 付近を読み書きする。

### 4.3 引用符と属性参照

HLASM の `'` は 2 つの意味を持つ。文字列を囲む引用符と、属性参照 (`L'FIELD`) の印である。
`DC A(L'FIELD)` を前者と読むと、開いたままの引用符として原文全体が壊れる。

属性の印と読むのは、直前が属性の文字で、<b>そのさらに前が名前の文字でない</b>ときだけである。
後半の条件がないと `DC 0D'0'` の `D` を属性と読む。

評価できる属性は通常の式の `L'`、マクロパラメタの `K'` / `N'`、配列 SET 記号の `N'`、
条件付きアセンブリの `T'` の一部である。`T'` は、先に生成された単純な `DC` / `DS` 記号、
機械命令の名前欄、数値の自己定義項、省略されたマクロ引数を扱う。
前方参照や複雑な定数など型を確定できない参照は診断する。

### 4.4 ソース内マクロの初期範囲

`MacroProcessor` は `HlasmReader` の文を受け、2 周の組み立てを始める前に展開する。同じ展開結果を
両方の周で使うので、マクロ中の `DC` / `DS` と前方参照で所在カウンタがずれない。プロトタイプの
位置・キーワード引数と名前欄引数、モデル文の変数置換、入れ子の呼出しを扱う。`&SYSNDX` は呼出し
ごとに増え、最初の 9999 回は 4 桁にゼロ埋めする。シーケンス記号はマクロ呼出しごとの局所範囲に
閉じる。条件付きアセンブリは単純な `SETA` / `SETB` / `SETC`、比較と `AND` / `OR` / `NOT`、
`AIF` / `AGO` / `ANOP` / `MEXIT` を扱う。`ACTR` は各マクロ呼出しと開放コードで別の
分岐カウンタを持ち、既定は 4096。`MNOTE` は 0〜3 を情報、4〜7 を警告、8 以上をエラーに
写す。添字付き `SETA` / `SETB` / `SETC` の宣言・代入・参照と、
宣言時の次元を越える要素も扱う。値を代入していない要素は型ごとの初期値を返し、
局所配列はマクロ呼出しごと、大域配列は呼出し間で保持する。
添字は正の整数式に限る。無限展開には深さと文数の上限も置く。

`COPY` は翻訳時にライブラリメンバの固定形式の原文をその位置へ挿入する。CLI は `-I`、
Maven は `src/main/asmlib` を SYSLIB 相当として使う。生成クラスは組立て済みの機械語を保持し、
実行時にライブラリを再探索しない。メンバの循環と欠落は診断し、メンバ内の `END` で展開を終える。
現段階の展開は条件付き
アセンブリより先に行うため、分岐で通らない `COPY` もメンバの存在を要求する。これは
IBM の条件付き処理との一致をまだ検証していない暫定範囲である。

未知の命令名と同名のライブラリメンバに `MACRO` / プロトタイプ / `MEND` があれば、
その定義を読み込み、依存するマクロ名も探索する。静的な命令名は先読みし、
`SETC` やマクロ引数から生成される命令名はモデル文の置換後に検索する。
後者もメンバ内の `COPY` を展開してからマクロ定義を処理する。

この範囲は [HLASM Language Reference](https://www.ibm.com/docs/en/SSLTBW_2.2.0/pdf/asmr1022.pdf)
の全マクロ言語ではない。属性 `T'` の前方参照・複雑な型、通常の記号に対する `K'` / `N'` の全範囲、
全システム変数の残り、配列 SET 記号の残る式は未対応である。マクロ引数の副リスト参照は
`&PARAM(n)` と入れ子の `&PARAM(n,m)`、これらへの `K'` / `N'` / `T'` を扱う。`&SYSLIST` の位置引数・
入れ子の副リスト・属性参照と、SETC / AIF の文字式における部分文字列も扱う。これら以外の資産については
未対応として診断し、組み立て成功とは数えない。

## 5. 断ると決めたもの

「近い値を黙って返すくらいなら、書けないと断る」。

| 範囲 | 断る理由 |
| --- | --- |
| 未定義のマクロと未対応の条件付きアセンブリ | 増分 2 は一部実装。知らない命令欄や対応できない式は<b>読み飛ばさない</b>。読み飛ばすと、展開されるはずだった命令が消えたまま組み立てが通る |
| `ICTL` | 桁の割当てを変える。既定の桁で黙って読むと原文と違う文を組み立てる |
| 倍率 `Sn` と指数 `En` の修飾子 | 倍率を 0 として組み立てると、値が 10 の冪だけずれる |
| 2 つ目以降の制御節、`ENTRY` / `EXTRN` | 外部参照の解決を持たない。増分で入れる |
| 浮動小数点の命令 (HFP / BFP / DFP の演算) | 桁の規則を突き合わせていない。定数 (`E` / `D` / `L` と拡張 `H` / `B` / `D`) は 2026-09-24 に組み立てられるようにした。HLASM の既定の丸め (HFP は方式 1、BFP と DFP は最近接偶数) に従う。値の後ろの丸めの指定 (`R1` など)、`(INF)` などの特別な値、長さの修飾子は断る |
| 権限命令、PSW 操作、クロスメモリ、ベクトル命令 | 実行環境の前提が違う |
| `START` の 0 以外の原点 | 節の先頭を 0 以外にすると変位と番地が一致しなくなる。番地は載せる側が決める |

## 6. 増分

| 増分 | 内容 | 状態 |
| --- | --- | --- |
| 1 前半 | 固定形式の読み取り、式、`DC` / `DS`、`USING`、機械命令の組み立て | **実装済** |
| 1 後半 | 線形アドレス空間と 16 本のレジスタ、命令インタプリタ、`CobolProgram` ABI への着地、COBOL からの `CALL` | **実装済** |
| 0 | `hlasm-corpus` の実行器 (6 状態) | **実装済**。Hercules との合成 26 ケースの実行比較も実施。実資産コーパスと残る命令の比較は未了 (P-175) |
| 2 | マクロと条件付きアセンブリ | **一部実装**。ソース内・ライブラリマクロ、`COPY`、副リスト、添字付き SET 記号、`&SYSLIST`、部分文字列、文字・算術関数、静的な前方属性、システム変数、`ACTR` と `MNOTE` を扱う。動的な先読み、`LOCTR` / `ISEQ` に依存するシステム値、z/OS 固有値と診断の再現は P-190 に残す |
| 3 | OS サービス (`WTO` / `GETMAIN` / `OPEN` / `GET` / `PUT` / `DCB`) と ABEND | 未実装 |
| 4 | CICS / IMS のスタブ (`DFHEIENT` / `DFHECALL`、`ASMTDLI`) | 未実装 |
| 5 | 主プログラムとしての実行 (`EXEC PGM=`) | **実装済**。設計 91 §6 の共通名前空間と `MixedLanguageJobTest` |

増分 0 を 1 のあとに置いたのは、測る対象が無い状態で実行器だけ作っても数が出ないためである。
組み立ての段は、モジュール内の試験が同じ役目を先に果たしている (§3)。

### コーパスの形

コーパスは<b>同梱しない</b> (要件 NFR-042)。取得元・版・SHA-256 は別の manifest に固定する。

```text
hlasm-corpus/
  decimal/
    add-01.asm        検査プログラム
    add-01.obj        期待する機械語 (16 進)。無ければ組み立ての受理だけを測る
    add-01.in         作業域の初期値 (16 進)。無ければゼロ
    add-01.out        期待する実行結果。無ければ実行しない
```

原文は 256 バイトの作業域を引数 1 つとして受け取る。実行の結果は戻りコードと作業域を
並べた文面であり、参照実装 (Hercules) 側では同じ作業域の範囲を `r 番地.長さ` で読み出せば
同じものが採れる。異常終了は `ABEND S0C7` の形で結果として数える。

```text
java -cp <classpath> dev.cobolonjava.verify.Main hlasm-corpus <置き場> [-o 報告]
```

### 暴走は「結果の不一致」ではない

命令数の上限まで戻ってこなかったことは、プログラム割込みとは<b>別の例外</b>にしてある
(`RunawayProgramException`)。割込みは資産の側の出来事であり、観測できる結果として数えてよい。
戻ってこないのは違う。測定の側から見れば「この 1 本は結果が取れなかった」であって
「結果が期待と違った」ではない。同じ例外にすると、暴走した 1 本が「異常終了した資産」として
結果の不一致に数えられ、数が嘘をつく。

これは試験を書いていて見つかった。最初は同じ例外だったので、返ってこないプログラムが
`CRASHED` ではなく `WRONG_OUTPUT` として数えられていた。

## 6.1 実行の層 (増分 1 後半)

### 番地空間

`AddressSpace` は区画の並びであり、区画は<b>実際の `byte[]` をそのまま</b>指す。写しを取らない
のは、決定 0002 が「同一領域を複数引数へ渡すエイリアシングを保たなければならない」と
定めているからである。同じ `Storage` を指す引数が 2 つあれば、番地空間でも同じ番地に重なる。

### 入口の状態 (標準リンケージ)

| レジスタ | 入口での値 |
| --- | --- |
| R1 | 引数表の番地。4 バイトの番地が並び、最後の番地は上位ビットが 1 |
| R13 | 呼ぶ側の 72 バイトの退避域 |
| R14 | 戻り番地。ここへ分岐したら実行を終える |
| R15 | 入口の番地。戻るときは戻りコード |

**R1 が指す表の並びが `DataView[]` に対応する。**調査レポートで「既存ポートに着地する良い知らせ」と
書いたのはここである。決定 0002 のバイト志向の呼出し契約と、そのまま噛み合う。

### 10 進命令は書き直さない

`AP` / `SP` / `MP` / `DP` / `ZAP` / `CP` の意味論は `cobol-runtime` の `Decimal` と
`PackedDecimal` に委ねる。この層は COBOL の算術のために<b>既に Hercules と突き合わせてある</b>。
**ゼロ結果の符号が命令ごとに違う**という、Principles of Operation からは読み取れない規則も
実測で入っている (暫定判断 P-001)。ここで書き直すと、その裏づけを捨てることになる。

### 組み立てられる命令のほうが、実行できる命令より多い

`SVC` は表にあるので組み立てられるが、実行できない。演算例外 (`S0C1`) として断る。
以前は `ED` / `EDMK` / `TRT` / `MVO` / `SRP` / `SLDA` / `SRDA` も同じだったが、2026-09-24 に
Principles of Operation の記述から実装した (暫定判断 P-173)。

### プログラムマスク

PSW のプログラムマスクを持つ。`SPM` で置き、`IPM` で読む。固定小数点のあふれは条件コード 3、
マスクの X'8' が立っていれば `S0C8`。10 進のあふれは上を捨てた値と条件コード 3、X'4' が
立っていれば `S0CA`。入口の値は X'4' としているが、実機では確かめていない (暫定判断 P-174)。

この差は意図している。組み立てと実行は別に測る層だからである (§3)。大事なのは、実行できない
ものを黙って近い値で通さないことである。

### Hercules との実行比較

増分 1 の実行の期待値は、Principles of Operation と、`cobol-runtime` が既に Hercules と
突き合わせてある層から来ている。`HerculesExecutionOracleTest` で同じ組み立て済み機械語を
Hercules と `Cpu` に流し、正常終了 19 ケースの作業域、R0 / R1 / R2、条件コードを比較して一致した。
さらにプログラム割込み 7 ケースでは、割込みコードと割込み時の作業域を比較して一致した。
対象には `MVC` の最大長、10 進桁あふれ、ゼロ除算、無効な数字ニブル、仕様例外、
`EX` の再帰実行、固定小数点桁あふれ、`PACK` / `UNPK`、`BXLE`、`EX` による分岐を含む。
全命令・全境界値を V2 と呼ぶものではない (P-175)。

## 7. 資産が無い状態での優先順位

対応対象の `.asm` は現在無い。対象資産を待たず、IBM の公開仕様で範囲と
失敗条件を決められる機能を次の順に進める。自己作成した期待値だけで V2 とは呼ばない (§3)。

| 順 | 作業 | 根拠と完了の条件 |
| --- | --- | --- |
| 1 | ライブラリマクロ | [IBM のマクロ命令の説明](https://www.ibm.com/docs/en/hla-and-tf/1.6.0?topic=reference-how-write-macro-instructions)に従い、明示的 `COPY`、静的な命令名、変数から生成される命令名からライブラリマクロを探索する。組立て後のクラスは SYSLIB を再探索しない |
| 2 | 条件付きアセンブリの属性と残る式 | [IBM の属性表](https://www.ibm.com/docs/en/hla-and-tf/1.6.0?topic=attributes-symbols-expressions)に従い、添字付き SET 記号、副リスト、`&SYSLIST`、部分文字列に加え、静的な前方参照の `T'` / `L'` / `S'` / `I'`、`D'` / `O'`、文字値・算術値の組み込み関数、システム変数を追加した。動的に生成される名前の先読み、外部関数・ホスト固有のシステム値、IBM HLASM の警告再現は P-190 に残す |
| 3 | OS サービス | `SVC` の入口と `WTO` / 記憶域・ファイルのサービスを既存のポートへ接続し、`DCB` と ABEND を扱う。入出力のバイト列と戻りコードを別々に測る |
| 4 | CICS / IMS | OS サービスとマクロ展開の土台の上に呼出しスタブを置き、既存の CICS / IMS ポートへ渡す |

命令実行の Hercules との比較 (P-175) はこの順番と並行して必要である。合成した 26 ケースは
実測で一致したが、実資産コーパスと残る命令の比較は続く。曖昧な仕様は暫定判断として記し、実測できるまで
近似値で通さない。そのほかの課題は[レポート §9](../research/hlasm-support-and-execution-requirements.md)に置く。
