# 設計 27: HLASM の組み立てと実行

## 1. 位置づけ

[方式検討レポート](../research/hlasm-support-and-execution-requirements.md) で出した答えは
「骨格は PL/I と同じでよいが、部品が 2 つ足りない」であった。本書はその実装を決める。

| レポートの結論 | この設計での扱い |
| --- | --- |
| 薄い殻 + `CobolProgram` ABI はそのまま使える | 増分 1 後半。`hlasm.generated.XXX` として着地する |
| 意味論はランタイムが持つ | 命令インタプリタが持つ。生成クラスは原文を渡すだけ |
| 足りない部品 1: レジスタと線形アドレス空間 | 増分 1 後半。`Storage` / `DataView` の下に敷く |
| 足りない部品 2: マクロと条件付きアセンブリ | 増分 2。<b>今は持たない。断る</b> |
| 外の基準は Hercules | 増分 1 の時点から、組み立ての突き合わせに使う |

## 2. 層

```text
[ HLASM の原文 (.asm) ]
          |
          v  HlasmReader     固定形式 → 文の並び
          |
          v  Assembler       2 周。所在カウンタと記号 → 機械語
          |
   [ ObjectModule ]          節の先頭からの変位で持つ。番地は載せる側が決める
          |
          +---------------------------+
          |                           |
          v  (増分 1 後半)             v  (増分 0)
  命令インタプリタ               組み立ての突き合わせ
  + 線形アドレス空間              - PoP から作った期待値
  + 16 本の汎用レジスタ            - cobol-oracle の Insn (Hercules で裏づけ済み)
          |
          v
  CobolProgram ABI → 既存のプログラム解決・JCL・CICS / IMS
```

## 3. 測る対象は 2 つある

COBOL と PL/I では「翻訳できたか」「実行結果が合うか」の 2 つだった。HLASM では 2 段になる。

| 段 | 測るもの | 基準 |
| --- | --- | --- |
| 1. 組み立て | 原文 → 機械語と変位 | Principles of Operation の命令形式。`cobol-oracle` の `Insn` |
| 2. 実行 | その機械語を動かした結果 | Hercules |

**この 2 つを同じ数に混ぜない。**混ぜると次の形で測定が嘘をつく。

> 自分のアセンブラが誤った機械語を作ると、Hercules も自分のインタプリタも<b>同じ誤った機械語</b>を
> 実行する。結果は一致し、測定は緑になる。しかし原文の意味は再現できていない。

CLAUDE.md §6 は「検査の道具が、処理系の失敗を作ってはならない」と言う。ここはその裏返しで、
**道具が処理系の成功を作ってしまう**形である。だから状態の数え方に `WRONG_OBJECT` を置き、
`WRONG_OUTPUT` と区別する。

`InsnAgreementTest` が第 1 段の最初の基準である。`Insn` は Hercules へ流す命令列を組むために
別に書かれたもので、その出力で実行した結果は実際に Hercules と突き合わせ済みである
(暫定判断 P-001 のゼロ結果の符号など)。2 つの表が食い違えば、どちらかが誤っていると分かる。

## 4. 組み立て

### 4.1 2 周する理由

1 周目で所在カウンタを進めて記号の値と長さ属性を決め、2 周目でバイト列を作る。

`USING` は 1 周目では<b>辿らない</b>。所在カウンタを動かさないからであり、辿ると
「まだ定義されていない `DSECT` を先に `USING` する」という普通の書き方が前方参照で落ちる。

リテラル (`=F'7'`) だけは 1 周目に<b>字面から</b>拾う。拾わないとプールの大きさが 1 周目に
決まらず、プールより後ろの番地が全部ずれる。

### 4.2 番地の解決

`USING` は<b>翻訳時の状態</b>である。実行時にあるのはレジスタの値だけで、どのレジスタが
どこを指しているという情報は機械語のどこにも残らない。だから 2 周目でも同じ順に辿り直す。

届く `USING` が 2 つ以上あれば変位の小さいほうを選び、同じなら番号の大きいレジスタを選ぶ。
届くものが無ければ<b>断る</b>。ここを黙って 0 番 (ベースなし) に倒すと、組み立ては通って
実行時に番地 0 付近を読み書きする。

### 4.3 引用符と属性参照

HLASM の `'` は 2 つの意味を持つ。文字列を囲む引用符と、属性参照 (`L'FIELD`) の印である。
`DC A(L'FIELD)` を前者と読むと、開いたままの引用符として原文全体が壊れる。

属性の印と読むのは、直前が属性の文字で、<b>そのさらに前が名前の文字でない</b>ときだけである。
後半の条件がないと `DC 0D'0'` の `D` を属性と読む。

扱う属性は `L'` だけである。`K'` `N'` `T'` は条件付きアセンブリのものであり増分 2 で入れる。
ここで先に読み分けると、支えていない書き方が「引用符が閉じていない」という別の理由で止まり、
原因が散る (CLAUDE.md §4)。

## 5. 断ると決めたもの

「近い値を黙って返すくらいなら、書けないと断る」。

| 範囲 | 断る理由 |
| --- | --- |
| マクロと条件付きアセンブリ | 増分 2。知らない命令欄はマクロ呼出しかもしれない。<b>読み飛ばさない</b>。読み飛ばすと、展開されるはずだった命令が消えたまま組み立てが通る |
| `ICTL` | 桁の割当てを変える。既定の桁で黙って読むと原文と違う文を組み立てる |
| 倍率 `Sn` と指数 `En` の修飾子 | 倍率を 0 として組み立てると、値が 10 の冪だけずれる |
| 2 つ目以降の制御節、`ENTRY` / `EXTRN` | 外部参照の解決を持たない。増分で入れる |
| 浮動小数点 (HFP / BFP / DFP) | 桁の規則を突き合わせていない |
| 権限命令、PSW 操作、クロスメモリ、ベクトル命令 | 実行環境の前提が違う |
| `START` の 0 以外の原点 | 節の先頭を 0 以外にすると変位と番地が一致しなくなる。番地は載せる側が決める |

## 6. 増分

| 増分 | 内容 | 状態 |
| --- | --- | --- |
| 1 前半 | 固定形式の読み取り、式、`DC` / `DS`、`USING`、機械命令の組み立て | **実装済** |
| 1 後半 | 線形アドレス空間と 16 本のレジスタ、命令インタプリタ、`CobolProgram` ABI への着地、COBOL からの `CALL` | **実装済** |
| 0 | `hlasm-corpus` の実行器 (6 状態) と Hercules 突き合わせ | 未実装 |
| 2 | マクロと条件付きアセンブリ | 未実装 |
| 3 | OS サービス (`WTO` / `GETMAIN` / `OPEN` / `GET` / `PUT` / `DCB`) と ABEND | 未実装 |
| 4 | CICS / IMS のスタブ (`DFHEIENT` / `DFHECALL`、`ASMTDLI`) | 未実装 |
| 5 | 主プログラムとしての実行 (`EXEC PGM=`) | 未実装 |

増分 0 を 1 前半のあとに置いたのは、測る対象が無い状態で実行器だけ作っても数が出ないためである。
組み立ての段は、モジュール内の試験が同じ役目を先に果たしている (§3)。

## 6.1 実行の層 (増分 1 後半)

### 番地空間

`AddressSpace` は区画の並びであり、区画は<b>実際の `byte[]` をそのまま</b>指す。写しを取らない
のは、決定 0002 が「同一領域を複数引数へ渡すエイリアシングを保たなければならない」と
定めているからである。同じ `Storage` を指す引数が 2 つあれば、番地空間でも同じ番地に重なる。

### 入口の状態 (標準リンケージ)

| レジスタ | 入口での値 |
| --- | --- |
| R1 | 引数表の番地。4 バイトの番地が並び、最後の番地は上位ビットが 1 |
| R13 | 呼ぶ側の 72 バイトの退避域 |
| R14 | 戻り番地。ここへ分岐したら実行を終える |
| R15 | 入口の番地。戻るときは戻りコード |

**R1 が指す表の並びが `DataView[]` に対応する。**調査レポートで「既存ポートに着地する良い知らせ」と
書いたのはここである。決定 0002 のバイト志向の呼出し契約と、そのまま噛み合う。

### 10 進命令は書き直さない

`AP` / `SP` / `MP` / `DP` / `ZAP` / `CP` の意味論は `cobol-runtime` の `Decimal` と
`PackedDecimal` に委ねる。この層は COBOL の算術のために<b>既に Hercules と突き合わせてある</b>。
**ゼロ結果の符号が命令ごとに違う**という、Principles of Operation からは読み取れない規則も
実測で入っている (暫定判断 P-001)。ここで書き直すと、その裏づけを捨てることになる。

### 組み立てられる命令のほうが、実行できる命令より多い

`ED` / `EDMK` / `TRT` / `MVO` / `SRP` / `SLDA` / `SRDA` / `SVC` は表にあるので組み立てられるが、
まだ実行できない。演算例外 (`S0C1`) として断る。

この差は意図している。組み立てと実行は別に測る層だからである (§3)。大事なのは、実行できない
ものを黙って近い値で通さないことである。

### まだ Hercules と突き合わせていない

増分 1 の実行の期待値は、Principles of Operation と、`cobol-runtime` が既に Hercules と
突き合わせてある層から来ている。**実行そのものを Hercules と突き合わせるのは増分 0 である。**
それまで、この層について「V2 (Hercules と一致) である」とは言わない (暫定判断 P-175)。

## 7. 未決

**最大の未決事項は対象資産が無いことである。**PL/I は `BNKSTMT.pli` と `IBLOGIN.pli` の 2 本が
subset の境界を決めた。HLASM でそれに当たるものを決めないと、どこまで実装するかが決まらない。

そのほかは[レポート §9](../research/hlasm-support-and-execution-requirements.md) に置いてある。
