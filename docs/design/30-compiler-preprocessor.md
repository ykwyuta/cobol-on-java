# 設計文書 30: cobol-compiler のプリプロセッサ (P0-b 第 1 増分)

| 項目 | 内容 |
| --- | --- |
| 対応要件 | FR-002, FR-003, FR-094, FR-193, ARC-8 |
| ステータス | 固定形式の読み取りと継続処理を実装済。`COPY` / `REPLACE` は未着手 |

## 位置付け

ARC-8 の方針は「手書きのプリプロセッサが文脈依存性をすべて吸収し、
正規化済みトークン列を ANTLR4 の構文解析器へ渡す」である。この増分はその手書き側の土台にあたる。

後段の構文解析器には<b>カラムも継続行も注釈行も見せない</b>。見せてしまえば、
宣言的に書けるはずの文法にカラム処理が染み出す。

## 出力: 1 文字ごとに出自を持つ正規化済みソース

プリプロセッサは固定形式のカラムを取り除き、継続行を連結し、注釈行を落とす。
その結果、正規化後のテキストは元のソースとは似ても似つかない形になる。

したがって `NormalizedSource` は<b>1 文字ごとに元のファイル・行・桁を保持する</b>。
位置情報を「行単位」ではなく「文字単位」で持つのは、継続行と (これから実装する) `COPY` 展開が
あるためである。正規化後の 1 行が元の複数行・複数ファイルにまたがるので、行単位では戻せない。

これがなければ、要件 FR-183 が求める「該当行・桁を指す診断メッセージ」は成立しない。

## 継続の規則が中心である

継続行 (7 桁目が `-`) の扱いは 2 通りあり、<b>直前の行が文字定数の途中で終わっているかどうか</b>で
変わる。

| 直前の行の状態 | 扱い |
| --- | --- |
| 文字定数が閉じていない | 直前の行は**72 桁まで定数の一部**とみなす (物理行が短くても空白で埋める)。継続行の B 領域の最初の非空白は引用符でなければならず、それを読み飛ばして続きを連結する |
| 定数の外 | 語の途中で切れているとみなし、継続行の最初の非空白から**区切りを入れずに**連結する |

### 72 桁までの空白補完を落としてはならない

1 番目の規則は見落としやすい。次のソースを考える。

```
      *    12345678901234567890 (桁)
           MOVE 'AB
      -    'CD' TO X.
```

`'AB` は 17〜19 桁にある。定数が閉じていないため、<b>20〜72 桁の 53 個の空白も定数の一部</b>に
なる。したがって定数の中身は `AB` + 53 個の空白 + `CD` の 57 文字である。

この規則を落とすと、<b>行末の空白を削ったソースと削っていないソースで定数の長さが変わる</b>。
実務のソースは行末が削られていることが多いため、物理行が短くても 72 桁まで補う実装にしている。

### 引用符 2 個は定数を閉じない

`'IT''S'` の途中の `''` は定数の中の引用符 1 個を表す。開閉の判定でここを取り違えると、
定数の終わりを誤検出して継続の分岐そのものが狂う。

## 誤りは黙って飲み込まない

- 標識領域に妥当でない文字があれば、ファイル名と行番号を添えて誤りとする
- 定数が閉じないまま継続行以外が続けば誤りとする
- 継続行が引用符で再開しなければ誤りとする

いずれも「なんとなく続ける」ことができてしまう場面である。要件 FR-181 の
「未対応のものは無視せず診断する」と同じ考え方で、静かに誤った解釈をしないことを優先する。

## 次の増分

1. `COPY` 文と `REPLACING` (擬似テキスト `==...==`) の展開。展開元のファイルと行を
   `Origin` に載せることで、コピー句の中の誤りもそのファイルを指せるようにする。
2. `REPLACE` 文。
3. 「島」の切り出し — PICTURE 句、`EXEC SQL` / `EXEC CICS`、コンパイラ指示文。
4. 自由形式 (`FREE`) の読み取り。
