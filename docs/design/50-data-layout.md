# 設計 50: データ部の記憶域割り付け

対象: 要件 FR-020, FR-030, FR-031, FR-032, FR-033 / 方針 ARC-4, ARC-7

## 位置付け

構文木 (設計 40) のデータ部から、<b>どのバイトがどの項目か</b>を決める。
`DataDivisionBuilder` が作り、`DataLayout` が持つ。

ここで初めて<b>コンパイラがランタイムの意味論を使う</b>。両モジュールがつながる最初の点である。

## 長さはランタイムに尋ねる

項目のバイト長は `NumericItem.byteLength()` と `Picture.size()` にそのまま任せる。
コンパイラが桁数から独自にバイト数を求めてはならない。

理由は 2 つある。ひとつは<b>ずれる余地を作らない</b>ため。もうひとつは、
V2 で Hercules と突き合わせて裏付けを取ったのは<b>ランタイムのほう</b>だからである。
コンパイラが別計算を持てば、裏付けのない数がひとつ増える。

| 項目 | 長さの出どころ |
| --- | --- |
| 数値 (`DISPLAY` / `COMP-3` / `COMP` / `COMP-5`) | `NumericItem.byteLength()` |
| 数値編集・英数字・英字 | `Picture.size()` |
| `COMP-1` / `COMP-2` | 4 / 8 (PICTURE を持たない) |
| 群項目 | 下位の項目から計算する |

## レベル番号は入れ子の深さではない

COBOL のレベル番号は「大きいほうが下位」という順序だけを表す。`01` の次が `05` でも
`02` でもよく、`05` の下に `10` が来ても `07` が来てもよい。深さとして扱うと、
現場のソースはたいてい通らない。

したがって<b>開いているレベルを積んで、番号の大小で閉じる</b>。新しい項目の番号以上の
レベルを積みから外し、残ったいちばん上が親になる。

`01` と独立項目 `77` は積みを空にして、それ自身の記憶域の先頭から始まる。

## REDEFINES は位置を巻き戻す

`REDEFINES` は記憶域を進めない。重ねる先と同じ位置から始め、次の項目は
<b>重ねる前の位置から</b>続く。

群項目の長さは「下位の項目の合計」ではなく<b>いちばん遠くまで届いた項目</b>で決める。
重ねた側のほうが長い場合があるためである (`01` レベルでは規格上も許される)。

重ねる先は<b>同じ親を持つ、自分より前の項目</b>から探す。見つからなければ誤りとする。
黙って位置を進めると、以降のすべての項目がずれる。

## OCCURS は 1 回分を繰り返す

下位を含めた 1 回分の長さを求め、回数だけ繰り返す。`DataItem` は 1 回分の
`length()` と反復を含めた `totalLength()` の両方を持つ。

`OCCURS m TO n DEPENDING ON` の可変長は、記憶域としては<b>最大の n</b> を確保する。
実際に使われる長さは実行時に決まるが、割り付けは最大で取る。

## 88 レベルは記憶域を占めない

条件名は直前の項目に付く。`ConditionName` として項目が持ち、値は `THRU` の範囲も
書けるようにしてある。66 レベル (`RENAMES`) は割り付けの規則が別物なので、
いまは誤りとして報告する。

## 未対応は黙って通さない

`USAGE INDEX` / `POINTER` / `NATIONAL` / `DISPLAY-1` はランタイムが未対応である
(暫定判断 P-006)。長さを勝手に決めると、以降の項目がすべてずれたうえで
<b>誤りが出ない</b>。したがって診断として報告する。

PICTURE のない基本項目、PICTURE を持つ `COMP-1` / `COMP-2` も同様である。

## 次の増分

1. `VALUE` 句の初期値。ランタイムの `NumericItem.encode` と図形定数を使って、
   記憶域の初期イメージを作る。
2. 名前の修飾 (`OF` / `IN`) と添字。いまは `findAll` が候補をすべて返すだけである。
3. `FILE SECTION` と `FD` 項目 (ファイル入出力の前提)。
4. 66 レベルの `RENAMES`。
5. `SYNCHRONIZED` による境界調整。いまは句を読み飛ばしている。
