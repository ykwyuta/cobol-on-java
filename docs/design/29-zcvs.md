# 設計 29: ZCVS で z/OS の決めごとを測る

CCVS85 ([設計 25](25-verification.md)) は<b>85 規格</b>を測る。全部通しても、次のことは
1 つも分からない。

- 詰め 10 進・ゾーン 10 進・2 進の<b>バイトの並び</b>と符号のニブル
- `TRUNC` / `NUMPROC` のような<b>翻訳オプション</b>で変わる値
- EBCDIC の照合順序、国字と DBCS
- `LOCAL-STORAGE`、`RETURNING`、副入口、ポインタといった<b>85 規格のあとの連絡</b>
- QSAM / VSAM の入出力状態の細かい値

どれも「資産をソース無修正で移す」ときに効くところである。ここを測る外の基準として、
[Zeus](https://github.com/ykwyuta/Zeus) の検査スイート <b>ZCVS</b> を使う。

## なぜ別の処理系のスイートなのか

Zeus は同じ目的 (z/OS の COBOL をホストの外で動かす) を持つ別の処理系であり、自分の
互換性を測るために ZCVS を書いている。こちらから見ると、<b>自分で書いた規則を自分の
テストで固定する罠の外にある</b> (覚え書き 3)。CCVS85 を置いた日と同じことが起きた。
最初の測定で、自分では思い付かなかった不備が並んだ。

ただし、ZCVS の期待値は Zeus の作者が公開仕様から書いたものであり、<b>z/OS で流した
結果ではない</b> (ZCVS の README がそう断っている)。落ちた判定は「こちらが違う」ことの
強い手がかりだが、証明ではない。直す前に公開仕様を読む。読んで ZCVS のほうが違うと
分かったものは、直さずに下の表へ書く。

## 流し方

```
java -cp <classpath> dev.cobolonjava.verify.Main zcvs <Zeus の zcvs> [-P プログラム名]... [-o 出力先]
```

スイートは<b>同梱しない</b> (要件 NFR-042)。ZCVS は GPL-3.0-or-later であり、Apache-2.0 の
成果物へは取り込めない。外にある置き場を指して動く。

道具 (`ZcvsRunner`) がやることは次のとおりである。

| 段 | 内容 |
| --- | --- |
| 流し方を読む | `manifest.toml` のプログラムごとの指定。断ることを期待する本 (`compile-error`)、翻訳だけを見る本 (`compile-only`)、CCSID、PARM、期待する復帰コード |
| 写し句 | 置き場の `copy`。`COPY ... OF COPYALT` は `copyalt` |
| 副プログラム | 区分の `lib` の全部を、呼ぶ側と同じ読み込み器へ入れる |
| 数える | 報告は CCVS85 と同じ形である。判定の数は<b>プログラムが自分で書いた集計</b>から読む。最後まで行かなかった本は「0 件落ちた」ではなく<b>壊れた</b>と数える |
| 時間の限り | 翻訳にも実行にも 60 秒 (覚え書き 6) |

負系は<b>断ったこと</b>だけを見る。`manifest.toml` の `diagnostic_contains` は Zeus の
診断の文面であり、こちらの文面とは合わない。例外で落ちたのは断ったうちに入れない。

## 翻訳できないだけでなく、動きが違っていたもの

「翻訳できない」は断っているので害が小さい。害が大きいのは<b>翻訳できて、値が違う</b>
ものである。ZCVS が見つけたのは次のとおりで、どれも CCVS85 は全部通っていた。

| 違っていたこと | 見つけた本 |
| --- | --- |
| `LOCAL-STORAGE` が呼び出しのたびに作り直されず、前の値が残り、再帰が外側の値を壊していた | ZP101A、ZP102A、ZP109A、ZP112A |
| `PROGRAM-ID ... IS INITIAL` を読むだけで、効かせていなかった | ZP109A |
| 符号なしの 2 進項目 (`PIC 9(4) COMP-5` に 65535) を、符号つきとして -1 に読み戻していた | ZD103A、ZD108A |
| NUMERIC の級条件が符号のニブル A〜F をどれも通し、符号なしの詰め 10 進は符号を見ていなかった | ZA106A |
| `OCCURS DEPENDING ON` の表を含む項目の `LENGTH OF` が、いちばん大きい形の長さだった | ZD105A |
| 可変長の表のうしろの項目を、いちばん大きい形の位置に固定していた | ZD113A |
| `DECIMAL-POINT IS COMMA` の下でも `NUMVAL` がピリオドを小数点として読んでいた | ZX109A |
| 「`IF A = 1 AND 条件名`」のあとの文の比較まで先読みし、正しい原文を構文誤りで断っていた | ZX102A |
| USING に並ばない連絡節の 01 を持つプログラムで PERFORM すると、内部の例外で落ちていた | ZP105A、ZP108A |
| 開く前のファイルに READ / WRITE / CLOSE をすると既定の様式 (80 byte) を覚えてしまい、あとの OPEN が宣言の様式にならなかった | ZF113A |
| 索引編成と相対編成が、開いていないファイルへのどの要求にも 42 を返していた (順編成は 47 / 48 / 49) | ZF104A |
| 相対編成で終わりまで読んだあとの番号読みが 46 になっていた | ZF110A |

| 同じ副鍵のレコードの並びが、閉じて開き直すと主鍵の順に戻っていた (P-087) | ZF108A、ZF112A |

## 自分のテストが狭いほうを固定していたもの

覚え書き 3 の表に、このスイートが足した行である。

| 自分のテスト | 実際は |
| --- | --- |
| 「`BY VALUE` は断る」(2 本) | 写しを渡せば表せる |
| 「副入口 (`ENTRY`) は断る」(2 本) | 段落を切って入口にできる |
| 「`TRUNC(BIN)` と `TRUNC(OPT)` は断る」 | ランタイムには初めから切り替えがあり、翻訳系が渡していなかっただけだった |

| 副鍵の並びを見る検査が「重複があっても 00」(3 本) | 続きがあれば 02 |

## CCVS85 も流し直した

ZCVS に合わせて直すたびに、規格の側を壊していないかを CCVS85 で確かめる。この一連の
増分のあと、動かした結果は<b>346 本、8,723 件のうち落ちた判定 1 件</b>で変わっていない。

流し直して、別のことが 1 つ見つかった。受理が 458 本中 443 本で、README の 444 本より
1 本少なかった。NC107A が `PERFORM 0000000000000000000000000001` のように<b>数字だけの
手続き名</b>を使っており、`ARITH(COMPAT)` の 18 桁の上限を入れた前の増分が、これを数字定数
として数えて断っていた。その増分のあと測り直していなかった (覚え書き 2)。手続き名を
検査から外して 444 本に戻した。

**2026-11-11 に流し直した結果**: 受理 444 / 458 本、実行は 346 本が全部通り 8,723 件の
うち 1 件落ちで変わらない。途中で受理が 3 本下がったのは、道具が埋める X-card 053 が
`RERUN EVERY 1000 RECORDS` と `OF ファイル名` を欠いていたためで、札を直した
(覚え書き 6)。比べ先の 2026-11-10 の報告 (443 本) から、「ARITH(COMPAT) の数字定数の
桁数」で断っていた 1 本が通るようになった。どの増分によるかは確かめていない。
コミット 6b66a59 のメッセージは、これを「続けて書いたプログラムの前の CBL 文」の
増分によると書いたが、CCVS85 に CBL 文は無いので誤りである。

## ZCVS のほうを直したもの (2026-11-11)

8 本は、こちらの診断のほうが公開仕様に合っていると判断して止めていた。権利者の
指示で <b>Zeus の側の原文を直し</b>、数に入るようにした。Zeus の自分のテスト
(`zeus-ccvs` の `zcvs`) は直した原文で通っている。<b>実機で確かめてはいない</b>
(暫定判断 P-191)。

| 本 | 直す前 | 直したあと |
| --- | --- | --- |
| ZA109A、ZX107A | 小数を持つ数値を英数字へ `MOVE` していた (落ちたときの枝の中)。MOVE の表が許していない | 数字編集項目を経て移す |
| ZA111A〜ZA115A | `01 UP REDEFINES ...`。`UP` は予約語である (`SET ... UP BY`) | `UPK` |
| ZS105A | `REPLACE ==OMEGA== BY ==FINAL==`。`FINAL` は予約語である | `OMICRON` |

直して流したら、<b>その奥にこちらの不備が 3 つあった</b> (覚え書き 2)。8 本が予約語で
止まっていたあいだは見えなかった。

- **GLOBAL の集団の中の項目を `CALL ... USING` で渡すと、呼ばれた側の書いた値が消えた。**
  分け合う領域 (GLOBAL、EXTERNAL) は呼び出しの前後で写しを取って合わせている。戻った
  ときに古い写しを書き戻していた。写しが自分の書き出したときのままなら読み込まない
  ことにした (`ProgramContext.load`)。EXTERNAL の項目を渡したときも同じだった
- **`REPLACE` が原文の終わりまで効いていた。** 別々に翻訳されるプログラムの終わり
  (いちばん外の `END PROGRAM`) で解ける。続けて書いた次のプログラムの語を置き換えていた
- **`NUMCLS(ALT)` を黙って捨てていた。** 知らないオプションとして警告して通し、
  既定の表で級条件を判定していた。値を変えるのに断っていなかった

`NUMPROC(PFD / MIG)` と `NUMCLS(ALT)` は、NUMERIC の級条件が通す符号の表として入れた。

| 指定 | 符号つきの項目で通る符号 |
| --- | --- |
| `NUMPROC(NOPFD)` / `NUMPROC(MIG)`、`NUMCLS(PRIM)` | C・D・F |
| `NUMCLS(ALT)` | A〜F |
| `NUMPROC(PFD)` | C・D、値が 0 のときの F |

符号なしの項目はどの指定でも F だけである。演算は、入力が優先符号であるかぎり
`NOPFD` と同じ結果になる。優先符号でない入力の `PFD` の結果は言語解説書が
「予測できない」としているので、`NOPFD` と同じに扱っている (暫定判断 P-194)。

## 磁気テープ — 2026-11-11

最後の 2 本 (ZF201M、ZF202M) は磁気テープの装置に依っていた。158 本すべてが通る。

- 割当てが装置を知る仕組みを足した (`DataSetCatalog.tape`)。ZCVS の道具は manifest が
  指す JCL の `UNIT=3480` などを読んで、その DD をテープにする
- テープのファイルは巻の境目を持つ。`CLOSE ... REEL / UNIT` は、書くときは次の巻を
  始め、読むときは残りを飛ばして次の巻の頭へ移る。読み終えた巻 (空の巻も) は自動で
  越える。境目はデータの隣のファイル (`.volumes`) に置く
- `OPEN INPUT ... REVERSED` は逆から読む。読めるのはテープだけで、ほかの媒体では
  37 にする (暫定判断 P-198)。以前は翻訳で断っていた
- テープの `OPEN / CLOSE ... WITH NO REWIND` は 07 でなく 00 である

巻のラベル (VOL=SER、標準ラベルの中身) と、装置の大きさで巻が切り替わることは
持たない。

**自分のテストが狭いほうを固定していたもの** (覚え書き 3)。「国字の部分参照は断る」
「国字の数字は断る」「`NSYMBOL(DBCS)` は断る」「国字編集は断る」「1399 は断る」。
どれも通すことを確かめる形に置き換えた。

**正しい理由で当たっていなかった負系**。ZE114N (符号つきの国字の数字に SIGN
SEPARATE が無い) と ZE115N (国字の群の中に別の USAGE) は、`GROUP-USAGE` を知らない
という理由で断れていた。受け付けたら通るようになったので、本当の理由で断るよう直した。

| 増分 | 通った本 | 入れたもの |
| --- | --- | --- |
| 小さい 5 つ | 134 | LE のサービス 5 つ、`INSPECT` の対象に関数、`CODE-SET`、`RERUN` の検査、続けて書いたプログラムの前の CBL 文 |
| 外部浮動小数点 | — | `PIC +99.99E+99` (DISPLAY の形) |
| 浮動小数点の受取側 | — | 除算とべき乗 (P-127 を書き直した) |
| ファイルまわり | 140 | `SAME` と `APPLY`、状態 39、`RECORDING MODE S / U` |
| ZF102A (Zeus 側を直した) | 141 | 「ディスクの `RECORDING MODE U` は状態 39」は Zeus の実装の制限だった |

**「読んで捨てる」と決めた句の中に、値を変えるものと断るべき誤りの両方があった。**
`CODE-SET` は ASCII で書くという指定であり、`RERUN` は `OF ファイル名` が欠けていれば
誤りである。読み飛ばしは診断も一緒に捨てる。

**自分が入れていた不具合。** `I-O-CONTROL` の指定の種類を `entry.SAME() == null` で
見ていた。ANTLR の取り出し口は並びを返し、無くても null にならない。`APPLY` や
`RERUN` の指定まで `SAME` として読み、そこに書かれたファイルの領域の共有を壊していた。
入れたばかりの `RERUN` の検査も同じ書き方をしていた。

## PL/I と HLASM

Zeus は同じ形のスイートを PL/I (ZPVS、68 本) と HLASM (ZHVS、125 本) にも持っている。
同じ道具で流す。`manifest.toml` の `language` で言語を決め、副プログラムは拡張子で
翻訳系を選ぶ (HLASM の検査が COBOL と PL/I の副プログラムを LINK する本がある)。

```
java -cp <classpath> dev.cobolonjava.verify.Main zcvs path/to/Zeus/zhvs -o zhvs-report.txt
java -cp <classpath> dev.cobolonjava.verify.Main zcvs path/to/Zeus/zpvs -o zpvs-report.txt
```

### HLASM (ZHVS) — 2026-11-11

| 測った時点 | 通った本 | 判定 |
| --- | --- | --- |
| 始め | 32 / 125 | — (通っていたのは「断ること」を見る本だけ) |
| 64 ビットのレジスター、再配置、外部呼び出し、QSAM | 51 / 125 | 171 / 175 |
| 浮動小数点 (HFP・BFP・DFP) と PFPO | 110 / 125 | 527 / 531 |
| 前方参照の EQU、節の再開、OPSYN、属性、OS のサービス | 125 / 125 | 577 / 577 |

門は 4 つあった。汎用レジスターが 32 ビットしか無い、番地定数を再配置していない、
V 型の外部参照が無い、DCB / OPEN / GET / PUT が無い、である。報告の副プログラムが
この 4 つを全部使うので、動かす本が 1 本も通らなかった。

**自分の診断が狭かったもの** (覚え書き 3)。どれも HLASM Language Reference が許している。

| 自分の診断 | 実際は |
| --- | --- |
| `undefined symbol` (EQU) | EQU はあとで定義される記号を使える |
| `the symbol is defined twice` (CSECT) | 同じ名前の CSECT は節の続きに戻る |
| `OPSYN is not supported yet` | 付け替えた時点の命令を指す表で足りる |
| `the scale and exponent modifiers are not supported` | 固定小数点の位取り (`FS2'1.5'`) |
| `a quoted string is not closed` | `L'=H'7'` の引用符は属性の印である |

**自分が入れていた不具合**。

- モジュールの記憶域を呼ぶたびに作り直していた。作業域の値が呼び出しをまたいで
  残らなかった。自分のテストは「記憶域は空」を正しいこととして固定していた
- R15 を RETURN-CODE へ渡していなかった
- 2 周目の演算項なしの `ORG` が、1 周目の最高位置へ飛んでいた
- 外の記号の入口を 31 ビットの上の端に置いていたので、`SAM24` のあいだは呼べなかった

**断るべきものを通していたもの**。乗算・除算の奇数のレジスター (ASMA029E)、
16 ビットに入らない即値、`SRP` の 10 以上の丸めの数字。

浮動小数点は Zeus の `hlasm/float.rs` と `hlasm/execute/floating/` を移した
(`FloatingPoint`、`FloatingUnit`)。値は整数の比で持ち、ホストの `double` を通さない。
持たないものは断る (暫定判断 P-196)。

`SELECT` は主語があれば WHEN の値と比べ、無ければ WHEN の式を真偽として見る。
当たる WHEN も OTHERWISE も無ければ ERROR を起こす (LRM "SELECT statement")。
実機と突き合わせていない。

`TITLE` はファイルを結ぶ DD 名を開くたびに決める (LRM "TITLE option")。PF103A では
`OUT` と `INP` の 2 つのファイルが同じ DD `XXXXX001` を開く。以前は `TITLE` を読まずに
ファイルの名を DD 名にしていたので、別々の (割り当ての無い) データセットになるところだった。
用意したデータセットは「ファイル名と DD 名の組」で引く。`ENV(V RECSIZE(n))` の n は
4 byte の RDW を含むので、データの最大長は n-4 である (Programming Guide "RECSIZE")。

マクロ前処理 (`PliMacroProcessor`) は Zeus の `preproc.rs` を移した。前処理の文が無い原文は
1 文字も変えない (注記も改行も)。ある原文は字句の並びに直して実行し、本文の字句は原文の
行に合わせて書き出すので、翻訳の診断の行は原文の行のままである。Zeus と違えたところは
2 つある。宣言していない名を前処理の式で参照すると、Zeus は空の文字にするが、こちらは
断る。数にならない文字を FIXED へ移すと、Zeus は 0 にするが、こちらは断る。どちらも
近い値を黙って返さないためであり、実機とは突き合わせていない (P-197)。

CONTROLLED の変数は、宣言した環境に世代の積み重ねを持つ。`ALLOCATE` は宣言をその環境で
し直して前の束縛を退避し、`FREE` で戻す。積んだ数が `ALLOCATION` である。引数で渡された
CONTROLLED を仮引数の名で `ALLOCATE` すると、呼んだ側の世代に積まれる (PS102A の `PUSH`)。
BASED の `ALLOCATE` は記憶域を取って番地を locator (`SET` か `BASED(P)` の P) へ入れる。
BASED の `INITIAL` を `ALLOCATE` で効かせることと、`AREA` / `OFFSET` はまだ持たず、断る。

断るべき側の検査 (PE113N、PE114N) は、以前から「`ALLOCATE` という文を知らない」で
断っていたので数の上では通っていた。ZPVS の道具は文面を照合しないので、正しい理由で
断っているかは自分のテストで確かめる (`StorageControlTest`)。

locator で修飾した参照 `Q->A` は、A の宣言の locator (`BASED(P)` の P) を一時的に Q の値に
して読み書きし、済んだら戻す。代入の右辺は入れ替える前に評価する。持つのは値の読み、
代入の左辺、`PUT` の項目だけで、`ADDR(Q->A)` や引数に書いたものは「宣言されていない名」で
断る。`NULL()` は X'FF000000'、`SYSNULL()` は 0 である (以前はどちらも 0)。POINTER の値は
位置ごとに振った番号なので (P-150)、`POINTERADD` は番号が指す記憶域の中で位置を進めた
番号を返し、記憶域の外へ出れば断る。

`LIKE` は以前、参照した名があるかを確かめるだけで<b>展開していなかった</b>。`DCL Q LIKE P`
は中身の無い宣言になり、`Q = P` が何を写すかは実行してみるまで分からなかった。ZPVS で
LIKE を使うのは負の検査 (PE104N、PE105N) と、それが「名がある」ことしか見ない正の検査
(PE104P、PE105P) だけだったので、数には出ていなかった。いまは `DEFINE STRUCTURE` /
`DEFINE ALIAS` の `TYPE` と合わせて、構文解析の前に宣言の字句の並びの上で展開する。
`LIKE` は要素の名と属性を写し、参照した構造の記憶域の種類と次元は写さない。小構造と
修飾した名の `LIKE`、`DEFINE ORDINAL` はまだ持たず、断る。

`DEFINED` も以前は<b>黙って読み飛ばしていた</b>。PS105A は翻訳が通り、5 つの判定が
すべて違う値で落ちていた。読み飛ばされた変数は自分の記憶域を持つので、基とつながらない。
いまは文字の重ね (`POSITION`) と iSUB の定義を持つ。iSUB の定義は、要素ごとに iSUB を
自分の添字に置いた基の要素を共有する。配列の単純な定義、構造の `DEFINED`、属性の違う
重ねは記憶域の並びの規則を確かめていないので、実行で断る。

同じ形 (知らない属性を黙って読み飛ばす) を宣言の型でも探した。型の属性を見つけられ
ないと、<b>前の項目の型を受け継いでいた</b>。`DCL F FLOAT DEC(6)` は構造になり、
`DCL Z COMPLEX FIXED DEC(7,2)` は実数になり、`DCL A BIN FIXED(31)` (語順が逆) と
`DCL D FIXED(5)` (底を省いた) も前の項目の型になっていた。名前付きの定数 `VALUE(10)` は
読み飛ばされて 0 だった。いまは語順と省略の既定 (FIXED だけなら DECIMAL、BIN / DEC だけなら
FLOAT) を読み、`VALUE` は INIT と同じに値を持つ。FLOAT、COMPLEX、AREA、OFFSET、HANDLE、
WIDECHAR、GRAPHIC、LABEL などまだ持たない型の宣言は、正しい PL/I なので翻訳では通し、
実行でその名を使ったときに止める。数は変わらない (51 / 68)。

`REFER` の構造 (`2 ITEMS(N REFER(CNT))`) は、BASED の構造を重ねるたびに記憶域の中の
対象 (CNT) の今の値を読んで形を決める。対象は REFER の配列より前にあるので、その位置は
仮の形で求められる。`ALLOCATE` は宣言の式 (N) で形を決めて記憶域を取り、対象に上限を
入れる。対象へ代入したら重ね直すので、後ろの要素 (TAIL) の位置が動く。REFER は BASED の
構造の中で、前に宣言したスカラーの要素だけを対象にでき、それ以外は翻訳で断る。

数の PICTURE は Zeus の `picture.rs` を移した (`PliPicture`)。9 Z * Y V , . / B $ S + - CR DB
T I R F(n)、浮動の字の並び、浮動小数の PICTURE (仮数 E|K 指数) を持つ。値は編集した字の像と
して記憶域に置き、算術では FIXED DEC(数字の位置の数, V より右の数字の数 - F) として読む。
記憶域の長さは像の長さであり、以前は数字の位置の数にしていた (9 と V だけの PICTURE で
しか合わない)。浮動小数の PICTURE は書けるが、値を読むことは FLOAT を持たないので断る。
編集の期待値は Zeus の検査をそのまま移したもので、実機と突き合わせていない。

`AREA(n)` は n byte と管理域 16 byte の記憶域で、管理域の頭の 4 byte に次の空きの位置を
置く。この管理域の形はこの処理系の約束であって、実機の形ではない (AREA の中身を
`UNSPEC` で見る資産とは合わない)。`ALLOCATE ... IN(a)` は次の空きから倍語の境界にそろえて
取り、溢れれば AREA 条件を起こす。解いた部分を再び使うことはまだ持たない。`OFFSET` は
AREA の頭からの位置である。AREA への代入は使った部分と管理域を写し、`EMPTY()` で空にする。

KEYED のファイルは COBOL と同じ索引付きデータセット (`IndexedDataSet`) に乗せた。鍵は
`ENV(KEYLENGTH(n) KEYLOC(k))` で決まり、書いていなければ翻訳で断る (VSAM の定義から読む
道をまだ持たない)。鍵の無いレコードは ONCODE 51、重なる鍵は 52 で KEY 条件を起こす。
番号は Zeus と同じで、実機と突き合わせていない。`LOCATE` は出力のバッファを取って locator に
入れ、そのファイルの次の `WRITE`・`LOCATE`・`CLOSE` の前に書き出す。`CLOSE` しないまま
終わったときのバッファはまだ書き出さない。

`GET STRING` は EDIT (F・A・X の欄) と LIST (空白か ',' で区切った項目、引用符の文字) を
持つ。点の無い F(w,d) の欄は d 桁の小数を含むとみなす。空白だけの F の欄は CONVERSION に
した (実機と突き合わせていない)。`PUT STRING DATA` は `名=値` を空白で区切って ';' で終える。
値の形は list-directed と同じにしたが、data-directed の空白の規則は確かめていない。
ファイルからの `GET` はまだ持たず、翻訳で断る。

門は内部手続きの引数だった。`CALL ZCHECK('名前', R=129.75)` のように式を渡す。
以前は名前しか受けなかった。式の引数を仮の変数で渡し、`CHAR(*)`、`RETURNS`、
`LEAVE` / `ITERATE`、`WRITE FILE ... FROM` を入れた。

いまの PL/I は Bank of Z の資産が使う部分だけを持つ小さな解釈系であり、ZPVS が
測る言語の広さ (入口変数、GENERIC、CONTROLLED、条件、前処理、ストリーム入出力) には
届いていない。この広さは継ぎ足しでは埋まらない。Zeus の `zeus-pli` (字句・構文・
意味・中間表現・実行の 5 段、約 2 万行) を移すのが次の増分である (暫定判断 P-197)。
