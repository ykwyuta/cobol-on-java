# 設計 29: ZCVS で z/OS の決めごとを測る

CCVS85 ([設計 25](25-verification.md)) は<b>85 規格</b>を測る。全部通しても、次のことは
1 つも分からない。

- 詰め 10 進・ゾーン 10 進・2 進の<b>バイトの並び</b>と符号のニブル
- `TRUNC` / `NUMPROC` のような<b>翻訳オプション</b>で変わる値
- EBCDIC の照合順序、国字と DBCS
- `LOCAL-STORAGE`、`RETURNING`、副入口、ポインタといった<b>85 規格のあとの連絡</b>
- QSAM / VSAM の入出力状態の細かい値

どれも「資産をソース無修正で移す」ときに効くところである。ここを測る外の基準として、
[Zeus](https://github.com/ykwyuta/Zeus) の検査スイート <b>ZCVS</b> を使う。

## なぜ別の処理系のスイートなのか

Zeus は同じ目的 (z/OS の COBOL をホストの外で動かす) を持つ別の処理系であり、自分の
互換性を測るために ZCVS を書いている。こちらから見ると、<b>自分で書いた規則を自分の
テストで固定する罠の外にある</b> (覚え書き 3)。CCVS85 を置いた日と同じことが起きた。
最初の測定で、自分では思い付かなかった不備が並んだ。

ただし、ZCVS の期待値は Zeus の作者が公開仕様から書いたものであり、<b>z/OS で流した
結果ではない</b> (ZCVS の README がそう断っている)。落ちた判定は「こちらが違う」ことの
強い手がかりだが、証明ではない。直す前に公開仕様を読む。読んで ZCVS のほうが違うと
分かったものは、直さずに下の表へ書く。

## 流し方

```
java -cp <classpath> dev.cobolonjava.verify.Main zcvs <Zeus の zcvs> [-P プログラム名]... [-o 出力先]
```

スイートは<b>同梱しない</b> (要件 NFR-042)。ZCVS は GPL-3.0-or-later であり、Apache-2.0 の
成果物へは取り込めない。外にある置き場を指して動く。

道具 (`ZcvsRunner`) がやることは次のとおりである。

| 段 | 内容 |
| --- | --- |
| 流し方を読む | `manifest.toml` のプログラムごとの指定。断ることを期待する本 (`compile-error`)、翻訳だけを見る本 (`compile-only`)、CCSID、PARM、期待する復帰コード |
| 写し句 | 置き場の `copy`。`COPY ... OF COPYALT` は `copyalt` |
| 副プログラム | 区分の `lib` の全部を、呼ぶ側と同じ読み込み器へ入れる |
| 数える | 報告は CCVS85 と同じ形である。判定の数は<b>プログラムが自分で書いた集計</b>から読む。最後まで行かなかった本は「0 件落ちた」ではなく<b>壊れた</b>と数える |
| 時間の限り | 翻訳にも実行にも 60 秒 (覚え書き 6) |

負系は<b>断ったこと</b>だけを見る。`manifest.toml` の `diagnostic_contains` は Zeus の
診断の文面であり、こちらの文面とは合わない。例外で落ちたのは断ったうちに入れない。

## 翻訳できないだけでなく、動きが違っていたもの

「翻訳できない」は断っているので害が小さい。害が大きいのは<b>翻訳できて、値が違う</b>
ものである。ZCVS が見つけたのは次のとおりで、どれも CCVS85 は全部通っていた。

| 違っていたこと | 見つけた本 |
| --- | --- |
| `LOCAL-STORAGE` が呼び出しのたびに作り直されず、前の値が残り、再帰が外側の値を壊していた | ZP101A、ZP102A、ZP109A、ZP112A |
| `PROGRAM-ID ... IS INITIAL` を読むだけで、効かせていなかった | ZP109A |
| 符号なしの 2 進項目 (`PIC 9(4) COMP-5` に 65535) を、符号つきとして -1 に読み戻していた | ZD103A、ZD108A |
| NUMERIC の級条件が符号のニブル A〜F をどれも通し、符号なしの詰め 10 進は符号を見ていなかった | ZA106A |
| `OCCURS DEPENDING ON` の表を含む項目の `LENGTH OF` が、いちばん大きい形の長さだった | ZD105A |
| 可変長の表のうしろの項目を、いちばん大きい形の位置に固定していた | ZD113A |
| `DECIMAL-POINT IS COMMA` の下でも `NUMVAL` がピリオドを小数点として読んでいた | ZX109A |
| 「`IF A = 1 AND 条件名`」のあとの文の比較まで先読みし、正しい原文を構文誤りで断っていた | ZX102A |
| USING に並ばない連絡節の 01 を持つプログラムで PERFORM すると、内部の例外で落ちていた | ZP105A、ZP108A |
| 開く前のファイルに READ / WRITE / CLOSE をすると既定の様式 (80 byte) を覚えてしまい、あとの OPEN が宣言の様式にならなかった | ZF113A |
| 索引編成と相対編成が、開いていないファイルへのどの要求にも 42 を返していた (順編成は 47 / 48 / 49) | ZF104A |
| 相対編成で終わりまで読んだあとの番号読みが 46 になっていた | ZF110A |
| 重複を許す副鍵で、同じ値が続くときの READ と重複を作った WRITE / REWRITE が、02 ではなく 00 を返していた | ZF108A、ZF112A |
| 同じ副鍵のレコードの並びが、閉じて開き直すと主鍵の順に戻っていた (P-087) | ZF108A、ZF112A |

## 自分のテストが狭いほうを固定していたもの

覚え書き 3 の表に、このスイートが足した行である。

| 自分のテスト | 実際は |
| --- | --- |
| 「`BY VALUE` は断る」(2 本) | 写しを渡せば表せる |
| 「副入口 (`ENTRY`) は断る」(2 本) | 段落を切って入口にできる |
| 「`TRUNC(BIN)` と `TRUNC(OPT)` は断る」 | ランタイムには初めから切り替えがあり、翻訳系が渡していなかっただけだった |
| 「開いていなければどの操作も 42」(2 本) | 42 は CLOSE だけ。READ 47・WRITE 48・REWRITE 49 |
| 副鍵の並びを見る検査が「重複があっても 00」(3 本) | 続きがあれば 02 |

## CCVS85 も流し直した

ZCVS に合わせて直すたびに、規格の側を壊していないかを CCVS85 で確かめる。この一連の
増分のあと、動かした結果は<b>346 本、8,723 件のうち落ちた判定 1 件</b>で変わっていない。

流し直して、別のことが 1 つ見つかった。受理が 458 本中 443 本で、README の 444 本より
1 本少なかった。NC107A が `PERFORM 0000000000000000000000000001` のように<b>数字だけの
手続き名</b>を使っており、`ARITH(COMPAT)` の 18 桁の上限を入れた前の増分が、これを数字定数
として数えて断っていた。その増分のあと測り直していなかった (覚え書き 2)。手続き名を
検査から外して 444 本に戻した。

## ZCVS のほうが z/OS で通らないと判断したもの

読んで、こちらの診断のほうが公開仕様に合っていると判断したもの。直していない。
<b>実機で確かめてはいない</b>ので、判断が違っていればここを直す (暫定判断 P-191)。

| 本 | 止まるところ | 判断の根拠 |
| --- | --- | --- |
| ZA109A、ZX107A | 小数を持つ数値を英数字へ `MOVE` している (落ちたときの枝の中) | Enterprise COBOL 言語解説書の MOVE の表。非整数の数値から英数字へは書けない |
| ZA111A〜ZA115A | `01 UP REDEFINES ...` | `UP` は予約語である (`SET ... UP BY`) |
| ZS105A | `REPLACE ==OMEGA== BY ==FINAL==` のあとの `01 FINAL` | `FINAL` は予約語である |

この 8 本は数に入れたままにしてある。除くと、判断が間違っていたときに気付けない。

## PL/I と HLASM

Zeus は同じ形のスイートを PL/I (ZPVS、68 本) と HLASM (ZHVS、125 本) にも持っている。
まだ流していない。COBOL と同じ道具の形で流せるはずであり、流せば同じように並ぶと
見ている。
