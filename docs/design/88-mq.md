## 1. 位置づけ

CardDemo には MQ を使う本が 3 本ある。

| 本 | 経路 | MQI |
| --- | --- | --- |
| `app-vsam-mq/cbl/CODATE01.cbl` | CICS。trigger monitor が起こし、`RETRIEVE` で MQTM を受ける | MQOPEN、MQGET (待ちあり、同期点の下)、MQPUT、MQCLOSE。`EXEC CICS SYNCPOINT` で確約 |
| `app-vsam-mq/cbl/COACCT01.cbl` | 同上。口座の VSAM を読んで返す | 同上 |
| `app-authorization-ims-db2-mq/cbl/COPAUA0C.cbl` | CICS。IMS と Db2 も使う | MQOPEN、MQGET、MQPUT1 (同期点の外、Expiry つき)、MQCLOSE |

これらはまず写し句 (`CMQGMOV`、`CMQODV` など) が無くて翻訳が止まっていた。写し句を処理系が用意し (§2)、
MQI の呼び出しを Java のプログラムとして program catalog に置く (§4) と、翻訳が通り MQ の呼び出しが動く。

Zeus は IBM MQ の C の client library を呼び、本物の待ち行列管理者へつなぐ。本処理系はまず<b>region の中に
待ち行列管理者を持つ</b>。外のブローカが無くても資産の要求と応答の経路を試せることを先にした。
外へつなぐときは、IMS の電文を JMS へ写す `cobol-ims-jms` (設計 78 §4、ADR-0014) の形に倣う (§7)。

## 2. 写し句

`MqSystemCopyBookResolver` が `CMQV`、`CMQODV` / `CMQODL`、`CMQMDV` / `CMQMDL`、`CMQPMOV` / `CMQPMOL`、
`CMQGMOV` / `CMQGMOL`、`CMQTMV` / `CMQTML` を返す。Db2 の `SQLCA` と同じく、写し句の置き場の<b>最後</b>に引く。
資産が自前の写し句を置いていればそちらを使う。

- <b>IBM の写し句の原文は参照しない</b>。欄の名前・型・長さ・初期値は公開文書の構造体の説明から作った
- 構造体は 10 段から始まる。資産は `01 MQ-OBJECT-DESCRIPTOR. COPY CMQODV.` と自分の 01 の下に写すからである。
  COPAUA0C は同じ `CMQODV` を 2 つの 01 の下に写し、`MQOD-OBJECTNAME OF MQM-OD-REQUEST` と引き分ける
- 記憶域は現行版の欄まで全部を持ち (MQOD 400、MQMD 364、MQPMO 176、MQGMO 112、MQTM 684 byte)、
  `VERSION` の既定値は 1 である。MQI は版を見てどこまで読むかを決める
- publish/subscribe の構造体 (MQSD など) は置かない。MQSUB を持つまでは、翻訳の段で断るほうが止まる場所が分かる

定数の Java の側 (`MqConstants`) と COBOL の側 (`CMQV`) は、`MqConstantsTest` が名前と値を突き合わせる。

## 3. 待ち行列管理者

| 部品 | 役割 |
| --- | --- |
| `MqQueueManager` | 名前、code page と CCSID、時計。局所待ち行列の定義 (`QueueDefinition`)、実行単位ごとの接続。Java の側から電文を置く・見る入口 (`put`、`messages`、`depth`) |
| `LocalQueue` | 見える電文と、作業単位の中の電文の数。開いている数、排他、GET / PUT の禁止 |
| `MqMessage` | 電文 1 つ: 記述子 (MQMD 2 版の byte 列そのまま) と中身 (プログラムの code page の byte 列) |
| `MqConnection` | 実行単位の接続: 開いた handle と作業単位 |

錠は待ち行列管理者に 1 つで、MQI の呼び出しはどれもその下で動く。MQGET の待ちは条件変数で待ち、
電文が見えるようになったとき (同期点の外の PUT、MQCMIT、MQBACK で戻った電文、Java の側の `put`) に起こす。

記述子を byte 列のまま持つのは、MQGET がそれをそのまま返すからである。欄を Java の値に開いて持つと、
プログラムが置いた欄を 1 つでも落とせば返す byte 列が変わる。

## 4. MQI

`Mqi.register(builder, manager)` が `MQCONN`、`MQCONNX`、`MQDISC`、`MQOPEN`、`MQCLOSE`、`MQPUT`、`MQPUT1`、
`MQGET`、`MQINQ`、`MQCMIT`、`MQBACK` を置く。IMS の `CBLTDLI` を `ImsRegion.register` が置くのと同じ形である。
引数は z/OS の形の記憶域のまま受け、完了コードと理由コードを最後の 2 つの引数へ書く。

### 4.1 接続

接続は<b>実行単位ごとに 1 つ</b>である (`JavaCallContext.runUnit()` を鍵にした弱い参照の表)。
`MQHC_DEF_HCONN` (0) は暗黙の接続で、CICS の下の資産がそうするように MQCONN を呼ばずに使える。
MQCONN は同じ接続を明示のものにし、その handle を返す。2 度目は `MQCC_WARNING` / `MQRC_ALREADY_CONNECTED`。
MQDISC は作業単位を確約して handle を閉じる (P-252)。

### 4.2 振る舞い

| 点 | 扱い | 根拠 |
| --- | --- | --- |
| 渡す順 | 優先度の高いもの、同じなら置いた順 | 公開文書の MSGDLVSQ(PRIORITY)。z/OS の既定 |
| 同期点 | `SYNCPOINT` / `NO_SYNCPOINT` のどちらも無ければ同期点の下 | 公開文書の z/OS の既定。ほかの環境では逆 |
| 作業単位 | 置いた電文は MQCMIT まで見えない。取った電文は MQBACK で元の位置へ戻り BackoutCount が 1 増える | 公開文書の MQMD BackoutCount |
| 深さ | 作業単位の中の電文も数える | MQIA_CURRENT_Q_DEPTH の説明 |
| 待ち | `MQGMO_WAIT` は WaitInterval (ミリ秒、-1 は限りなく) だけ壁時計で待つ | 公開文書 |
| 切り詰め | 既定は電文を残して `MQCC_WARNING` / 2080、`ACCEPT_TRUNCATED_MSG` なら取って 2079。どちらも入る分の中身と記述子を返す | 公開文書の 2079 / 2080 |
| 突き合わせ | MsgId / CorrelId。MQGMO 1 版は両方を見る。`MQMI_NONE` / `MQCI_NONE` は問わない | 公開文書の MatchOptions |
| 記述子 | 優先度・永続性の「定義に従う」、CCSID の `MQCCSI_Q_MGR` を置いた時に定義の値に置き換える。Expiry は返すときに残りの時間 | 公開文書 |
| MsgId | `MQMI_NONE` か `MQPMO_NEW_MSG_ID` なら振る。'CSQ ' と管理者の名前の先頭 4 文字で始める | P-253 |
| 文脈 | 既定の文脈で PutApplType と UTC の PutDate / PutTime を置き、利用者や応用の名前は空白 | P-253 |

### 4.3 作業単位と同期点

接続は実行単位の作業単位に加わる (`RecoverableResources`、`cobol-runtime`)。runtime は MQ の型を知らず、
`RecoverableResource` の `commit` / `backout` / `end` を呼ぶだけである。

| いつ | どうなる |
| --- | --- |
| `MQCMIT` / `MQBACK` | その接続の作業単位を確約・取り消す |
| `EXEC CICS SYNCPOINT` / `SYNCPOINT ROLLBACK` | 一時データの変更と同じ場所 (`CicsRuntimeOps.syncpointCondition`) で、加わった資源を確約・取り消す |
| 実行単位が正常に終わる (session を閉じる) | 確約し、handle を閉じる。z/OS の実行単位の終わりの暗黙の同期点と同じ |
| 実行単位が異常に終わる (session が失敗した、CICS の task が正常に返らなかった) | 取り消し、handle を閉じる。取った電文は BackoutCount を 1 増やして戻る |

<b>2 相の確約ではない</b> (P-254)。CICS の task の終わりでは、MQ は session を閉じるときに確約し、そのあとで
task の境界が Db2 の UOW を、続いて一時データを確定する。Db2 の確定が失敗しても MQ の確約は戻らない。

### 4.4 断るもの

それらしい理由コードを返すと、資産は「MQ がそう言った」として別の経路へ進む。持たないものは
`UnsupportedOperationException` で止める。

- 待ち行列でない対象 (MQOT_Q_MGR、名前リスト、topic)、分配リスト、別名・模型・遠隔の待ち行列
- browse、`MQGMO_LOCK`、`SET_SIGNAL`、電文のグループと区分、`MarkSkipBackout`
- 文脈の受け渡しと設定 (`MQPMO_PASS_*`、`SET_*`)、別の利用者の権限
- 報告電文 (MQMD Report の COA / COD / 例外など)
- 中身の変換 (`MQGMO_CONVERT` で CCSID が違うとき)
- MQINQ の待ち行列の属性のうち深さ・上限・禁止・開いている数・名前・記述でないもの。MQSET、MQSUB、MQCB

## 5. 確かめたこと

`cobol-mq` の試験はすべて、写し句を写した COBOL を翻訳して `CALL 'MQxxx'` から呼ぶ (`MqProgram`)。
写し句と MQI を同じ道で通すためである。

- PUT した 3 通が GET で同じ順に返り、空なら `MQCC_FAILED` / `MQRC_NO_MSG_AVAILABLE`
- 優先度の順。同期点の下の PUT は確約まで見えず、取り消しで消える。取り消した GET は戻り BackoutCount が増える
- 切り詰めの 2 通り、CorrelId の突き合わせ、MQPUT1 の MsgId と文脈と Expiry、理由コード (2085、2037、2019、
  2044、2018)、MQCONN の 2002 と 2058、MQDISC の確約、MQINQ の深さ、待ちのあいだに置かれた電文の受け取り
- 持たない選択 (browse) は理由コードを作らずに止まる
- 実行単位が異常に終われば、同期点の下の PUT と GET は取り消される
- CICS の task (`MqCicsTaskTest`): CODATE01 と同じ形で、RETRIEVE で受けた MQTM の待ち行列から要求を取り、
  応答を同じ MsgId / CorrelId で置き、`EXEC CICS SYNCPOINT` で確約する。task が ABEND すれば最後の
  SYNCPOINT より後の GET と PUT は取り消される (SYNCPOINT の口を外すと、この試験が落ちることを確かめた)

CardDemo の CODATE01 そのもの (コーパスの原文) を、この形で CICS の task として流した (試験には入れていない。
コーパスは同梱しないため)。要求 1 通に対し、`SYSTEM DATE : 10-20-2026SYSTEM TIME : 13:11:27` の応答
(1000 byte、Format `MQSTR`、要求の CorrelId) を `CARD.DEMO.REPLY.DATE` に置き、要求の待ち行列を空にして、
最後の MQGET の待ち (5 秒) のあと終わった。task には ASKTIME のための地方時を構成する必要がある。

CardDemo の数 (`tools/verify/measure-apps.sh`): 写し句を足して 29 → 31 本 (COACCT01 と CODATE01 が通った)。
COPAUA0C は MQ の箇所を越え、`EXEC DLI` で止まる。
