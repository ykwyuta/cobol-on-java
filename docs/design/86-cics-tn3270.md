# 設計 86: 3270 端末を TN3270 で受ける CICS の入口

| 項目 | 内容 |
| --- | --- |
| 状態 | 第 1 増分を実装 (experimental) |
| 対応要件 | FR-161〜FR-167 (端末と BMS)、設計 79 §8、設計 83 §4・§7 |
| 検証レベル | V1。外の 3270 エミュレータ `s3270` (x3270 系 4.1) で TN3270E と素の TN3270 を動かした |
| 場所 | `cobol-cics` の `dev.cobolonjava.cics.tn3270` |

## 1. 位置づけ

ブラウザの入口 (設計 81 §5) は Spring MVC の上にあり、画面は HTML で描く。ホストの資産を使っている
現場の端末は 3270 エミュレータであり、利用者の手順 (CLEAR して TRANSID を打つ、PF キー、MDT) も
3270 のものである。そこで、<b>Spring に依らず JDK だけで動き、3270 エミュレータがそのままつながる</b>
入口を `cobol-cics` に置いた。

方式は Zeus (`zcics --serve`、`crates/zeus-cics/src/tn3270.rs`) と同じにした。

| 点 | Zeus | 本処理系 |
| --- | --- | --- |
| 伝送 | TN3270 (RFC 1576) と TN3270E (RFC 2355) を同じ port で受ける。TN3270E を先に申し出る | 同じ |
| 画面 | BMS の画面を Erase/Write の SF / SFE、SBA、IC にして送る | 同じ。拡張属性の有無は型名の `-E` で決める (Zeus は Read Partition Query で聞く) |
| 入力 | Read Modified の SBA と field のデータを画面の模型へ当てる | 同じ。番地を直前の BMS の画面の field の名前に戻し、RECEIVE MAP が照合する |
| 確かめ方 | `tools/tn3270-test.sh` が `s3270` に台本を流す | `Tn3270EmulatorTest` (cobol-compiler) が翻訳した COBOL を動かし、`s3270` に台本を流す |

## 2. 部品

| 部品 | 役割 |
| --- | --- |
| `Tn3270Connection` | Telnet の取り決めと記録の読み書き。TN3270E の DEVICE-TYPE / FUNCTIONS、素の TN3270 の TTYPE / BINARY / EOR。読みの時間切れで途中の記録を失わない |
| `Tn3270Device` | 端末が名乗った型 (`IBM-3278-2-E` など) から既定と代替の画面の大きさを決める |
| `Tn3270DataStream` | 中立な画面 (`CicsTerminalScreen`) から 3270 データストリームを作り、Read Modified を番地とデータに分ける |
| `Tn3270Server` | port で受け、端末 1 台に virtual thread 1 本。端末を `CicsTerminalRegistryPort` に登録し、`CicsTaskCoordinator` で task を起こす |
| `Tn3270Main` | コマンド行から 1 つの領域を起こす。`--bms`、`--transaction TRAN=PROGRAM`、`--port` |

`cobol-cics` は `cobol-runtime` だけに依る、という決まり (設計 00) を保つ。使うのは `java.net` の
socket と virtual thread だけである。

## 3. 端末の 1 回の入力

1. 端末を lease する。端末へ出す task (START TERMID) が動いていれば入力は動かさず、警告音つきで
   キーボードを開ける
2. 端末が疑似会話の途中 (`RETURN TRANSID` のあと) なら、その TRANSID で task を起こす。入力は直前に
   送った BMS の画面と照合して `BmsTerminalInput` にする
3. 途中でなければ、入力のデータの先頭の語 (先頭の空白を飛ばし、空白か 4 文字まで) を TRANSID にする。
   CLEAR と PA は何も起こさずキーボードを開ける
4. `RETURN IMMEDIATE` は端末の入力なしで続ける (8 回まで。ブラウザの入口と同じ)
5. task が送った最後の画面を送る。画面を送らずに終わった task は、画面をそのまま残してキーボードだけを開ける

入力を待つ間は `poll` の間隔で端末の登録を延ばし、端末へ出す task が置いた画面の版が進んでいれば送る
(設計 83 §7 と同じ版の仕組み)。

## 4. データストリーム

- 画面は Erase/Write で送る。map が 24 x 80 に入らず、代替の大きさ (model 5 の 27 x 132 など) に入るなら
  Erase/Write Alternate。どちらにも入らなければ送らずに通知を出す
- field ごとに SBA で属性 byte の番地へ行き、SF (拡張属性を受ける端末で色か強調があれば SFE) を置き、
  データを続ける。データの無い位置は Erase の null のまま残す。端末は null を送り返さないので、
  打った値の後ろに空白が付かない
- 属性 byte は保護 X'20'、数字 X'10'、明るい X'08'、暗い X'0C'、MDT X'01' を 6 bit の表で印字可能な
  byte にする。ASKIP は保護と数字。FSET と画面の記録の MDT は MDT を立てる
- WCC は keyboard restore (BMS の FREEKB)、alarm、reset MDT
- cursor は画面の記録の位置に SBA と IC で置く。位置が決まっていなければ IC を置かず、3270 の既定の
  0 番地になる
- buffer の番地は 4096 未満なら 12 bit、それ以上なら 14 bit で書く。読むときは上 2 bit で見分ける

入力の field は、データの番地 = 属性 byte の番地 + 1 で画面の field に当てる。保護 field、名前の無い
field、画面に無い番地は使わない (FSET の保護 field は端末が送り返すが、RECEIVE MAP は画面の記録の
MDT から読む)。

## 5. 端末の名前

| 端末が求めたもの | 端末の名前 (EIBTRMID) | LU 名 |
| --- | --- | --- |
| LU 名 (TN3270E の CONNECT、素の TN3270 の `型@LU`) | LU 名の末尾 4 文字。CICS の自動導入の既定の program が NETNAME から TERMID を作る規則と同じ | 求めた名前 |
| 何も求めない | 登録が選ぶ `W` + 36 進 3 桁 | 端末の名前 |

同じ末尾 4 文字の別の LU は DEVICE-IN-USE で断る。

## 6. 確かめたこと

`Tn3270EmulatorTest` が、BMS の map を COPY した COBOL を翻訳し、入口を起こして `s3270` に台本を流す。

| 場面 | 端末に出たもの |
| --- | --- |
| TN3270E (`3279-2-E`) で接続し `grt1` と打つ | map。cursor は IC の field (2 行 13 桁、0 起点) |
| 名前を打って Enter | `HELLO, ALICE!`。COMMAREA の数が 2 |
| 何も打たずに Enter / CLEAR | MAPFAIL の文。端末の MDT は SEND MAP ERASE で消えている |
| PF3 | SEND TEXT の文 |
| 定義の無い TRANSID | DFHAC2001 |
| 素の TN3270 (`N:` の接続) で ABEND | DFHAC2206。次の入力は新しい会話になる |
| LU 名 `COJLU042` を求める | EIBTRMID が `U042` |

`Tn3270DataStreamTest` と `Tn3270ServerTest` (cobol-cics) は byte の並び、素の TN3270 の取り決め、
FUNCTIONS の求め返し、START TERMID の画面の配達を確かめる。<b>これらの期待値は自分で書いたもの</b>
であり、外の基準は `s3270` の試験だけである。

## 7. 未実装・未検証

暫定判断 P-191 に書いた。主なもの:

- sign on (CESN / CESF) が無い。user ID は構成の既定の user (DFLTUSER) だけ。`Tn3270Main` は既定で
  loopback だけで受ける
- TLS (TN3270 over TLS、STARTTLS)、印刷装置 (ASSOCIATE)、SYSREQ、構造化 field (Read Partition Query) が無い
- TN3270E の FUNCTIONS を 1 つも受けない (BIND-IMAGE、RESPONSES)
- 疑似会話の途中でない端末の入力は TRANSID の後ろを捨てる (`RECEIVE` の INTO で読む口が無い)
- DFHAC の通知の文面と、画面を送らなかった task のあとにキーボードを開けることは、実機の画面と
  突き合わせていない
- DBCS (IBM-930 / 939) の画面は、混在コードページの符号化が SO / SI を置くことに頼っている。
  s3270 の `-codepage cp939` で測っていない
