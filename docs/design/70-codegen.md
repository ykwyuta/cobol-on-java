# 設計 70: コード生成

対象: 要件 FR-013, FR-024, FR-026, FR-060 / 方針 ARC-3, ARC-7

## 位置付け

文の並び (設計 60) と記憶域の割り付け (設計 50) から、JVM のクラスファイルを作る。
`ProgramGenerator` が ASM で直接バイトコードを書き出し、`CobolCompiler` が
ソース 1 本から通しで動かす。

ここで<b>翻訳したものが実際に動く</b>ようになった。

## 生成コードは位置を決めて動詞を呼ぶだけである

生成したクラスは `CobolProgram` を実装し、記憶域の位置を決めて `Ops` を呼ぶ。
意味論そのものは持たない。

```
Ops.moveAlphanumeric(Ops.read(storage, 0, 3), storage, 3, 3, false, CP);
```

この分け方には理由がある。<b>V2 で Hercules と突き合わせて裏付けを取ったのは
ランタイムのほう</b>である。生成コードがその経路をそのまま通れば、裏付けは
生成コードにも及ぶ。逆に生成コードが独自にバイトを組み立てると、
そこだけ裏付けのない実装がひとつ増える。

障害が出たときに「意味論の誤りか、コード生成の誤りか」を切り分けられる点も同じ理由による
(方針 ARC-7)。

`Ops` はランタイム側に置いた薄い層で、記憶域の位置と動詞をつなぐだけである。
生成するバイトコードを短く保ち、バイトコードの誤りが入り込む余地を減らすために置いている。

## 翻訳時に決まるものは定数フィールドに置く

PICTURE の解析、`NumericItem` の組み立て、文字定数の符号化は<b>いずれも翻訳時に決まる</b>。
静的初期化子で 1 度だけ作り、手続きの中では参照するだけにする。

バイト列はクラスファイルの文字列定数から `ProgramSupport.bytes` で復元する。
ISO-8859-1 は 0〜255 をそのまま 1 バイトへ写すので、<b>任意のバイト列を文字列定数 1 個で
運べる</b>。初期イメージをバイトごとに組み立てるバイトコードを吐かずに済む。

## 初期イメージは複製して返す

`initialStorage()` は定数フィールドの複製を返す。実行のたびに書き換えられるため、
そのまま渡すと 2 回目の実行が 1 回目の結果から始まってしまう。

## 誤りが出たらクラスファイルを作らない

生成は 2 段になっている。まず文をたどって命令の並びと必要な定数を決め、
そこで誤りが出たら<b>クラスファイルを書き出さない</b>。半端なクラスを返すと、
呼び出し側が誤りを見落としたときに実行時まで問題が残る。

`CobolCompiler` も同じ考えで、構文解析 → 割り付け → 初期イメージ → 手続き部 →
コード生成の順に進み、誤りが出た段でそこから先へ進まない。割り付けが決まっていない
状態で手続き部を解いても、意味のない誤りが山のように出るだけである。

## 除算の商の桁数は受取項目に合わせる

加減乗の結果の桁数は被演算子から決まるが、<b>除算だけは決まらない</b>。
したがって受取項目の小数部を見て決めるほかない。

このため、算術文の計算は<b>受取項目ごとにまるごと出す</b>。受取項目が複数あって
小数部が違えば、計算そのものが変わりうるからである。`ROUNDED` も受取項目ごとに
書けるので、丸めモードも受取項目ごとに決まる。

## 条件は「真のとき飛ぶ」と「偽のとき飛ぶ」の両方を出す

条件のコード生成は `emitCondition(条件, 飛び先, 真のときに飛ぶか)` の形にした。
向きを 2 つ持つのは<b>`AND` と `OR` の短絡</b>のためである。

| | 偽のときに飛ぶ | 真のときに飛ぶ |
| --- | --- | --- |
| `A AND B` | A で飛ぶ、B で飛ぶ | A が偽なら下へ抜ける印へ、B で飛ぶ |
| `A OR B` | A が真なら下へ抜ける印へ、B で飛ぶ | A で飛ぶ、B で飛ぶ |

片方の向きしか持たないと、どちらかで必ず余計な分岐と反転が要る。
`NOT` は向きを反転して内側へ渡すだけで済む。

`IF` は「条件が成り立てば下へ抜け、成り立たなければ `ELSE` へ飛ぶ」形に出す。

## 段落は別々のメソッドにする

段落をそれぞれ別のメソッドとして出す。素直に流れる実行は `run` が上から順に呼び、
`PERFORM P` は P のメソッドだけを呼ぶ。`PERFORM A THRU B` は範囲の段落を順に呼ぶ。

この形にすると<b>「`PERFORM` は次の段落へ流れ込まない」という規則が自然に出る</b>。
入れ子の `PERFORM` も JVM の呼び出し規約がそのまま面倒を見てくれる。

代わりに `GO TO` が書けない。段落の途中から別の段落へ飛ぶのは、メソッド呼び出しでは
表せないためである。`GO TO` を含むプログラムだけ別の形 (段落全体を 1 つのメソッドにして
分岐する形) へ切り替える方針を暫定判断 P-029 に記録した。

### 繰り返しの指定と中身は独立に決まる

`PERFORM` の中身は<b>段落の呼び出しか、その場に書いた文か</b>のどちらかで、
繰り返しの指定は 1 回・回数・条件のいずれかである。両者は直交するので、
中身を 1 回分の命令として作り、指定に応じて包む形にした。

`UNTIL` の条件は<b>やめる条件</b>である。`WITH TEST AFTER` なら中身を 1 度
実行してから条件を見る。

## ON SIZE ERROR は被演算子を局所変数へ取る

`ON SIZE ERROR` の指定があるかどうかで<b>桁があふれたときに受取項目に何が残るか</b>が
変わる。指定があれば受取項目は変わらず、なければ上位桁を切り捨てた値が入る。
ランタイムの `Arithmetic.store` と `storeChecked` を呼び分けるだけである。

0 除算も条件を立てる。ただしこちらは<b>割る前に除数を調べる</b>必要があり、
計算の途中で分岐すると作用対象のスタックが揃わなくなる。したがって
`ON SIZE ERROR` つきの算術文では、被演算子をいったん局所変数へ取ってから
除数を調べ、そのあとで畳む。

受取項目ごとに条件を見て、<b>収まったものだけが書き換わる</b>。
どれか 1 つでも条件が立てば、最後に `ON SIZE ERROR` の文を通る。

## 位置は「定数の分をまとめてから変数の分を足す」

添字がすべて定数なら位置は翻訳時に決まり、定数を積むだけでよい。
データ項目で書いた添字が混ざる場合は、<b>定数の分をまとめてから、
変数の分を実行時に足す</b>。

```
位置 = 項目の変位 + Σ (添字 - 1) x その表の 1 回分の長さ
```

多次元の表でも同じ式である。定数の添字はその場で畳み込まれるので、
`WS-CELL (2, WS-J)` なら 1 つ分の足し算しか出ない。

部分参照の開始位置も同じ形で足す。ただし<b>長さは翻訳時に決まっていなければならない</b> —
図形定数を受取項目いっぱいに広げる処理が翻訳時に行われるためである (暫定判断 P-027)。

## DISPLAY は実行時の入口を引き回す

生成コードが大域の状態に触れないよう、`ProgramContext` を引数として引き回す。
`run` と段落のメソッドはどれも記憶域と実行時の入口の 2 つを取る。
試験で出力を捕まえられるのも、大域に書かないからである。

記憶域の中身は EBCDIC のバイト列なので、コードページで文字へ直してから書く。
<b>データセットへの書き出しとは扱いが違う</b> — そちらは生バイトのままであり、
変換するのは人が読む出力だけである。

`COMP` や `COMP-3` の項目はそのまま出しても読めないため、同じ桁数・同じ小数部の
`DISPLAY` 項目として符号化し直す。符号付きなら<b>符号は最後の桁に重なる</b> — 
`-12` は `01K` になる (`K` は EBCDIC の `D2`、負のゾーンを持つ 2)。
見た目は驚くが、参照実装の `DISPLAY` はこの形である。

## 生成したクラスはそのまま起動できる

生成したクラスに `main` を出す。翻訳したものを `java cobol.generated.HELLO` で
動かせるので、<b>間に何も挟まずに確かめられる</b>。

起動口は `dev.cobolonjava.compiler.Main` である。

```
cobolc [-d 出力ディレクトリ] [-I コピー句ディレクトリ] [--free] ソース...
```

## いま生成できる範囲

`MOVE` の 3 種類 (英数字・数値・数字編集)、算術文 4 つ (`GIVING` と `ROUNDED` を含む)、
`IF`、`EVALUATE`、`PERFORM`、`DISPLAY`、`STOP RUN` / `GOBACK`、`CONTINUE`、
算術文の `ON SIZE ERROR`。定数・図形定数・`ALL` の送出。
添字は定数でもデータ項目でもよく、多次元の表も扱える。部分参照の開始位置も同じ。

部分参照の<b>長さ</b>にデータ項目を書いた形は、まだ生成できない (暫定判断 P-027)。
`COMPUTE` は文法が受け付けない (暫定判断 P-028)。

## 次の増分

1. `PERFORM VARYING` と `GO TO` (暫定判断 P-029)。
2. `STRING` / `UNSTRING` / `INSPECT` — ランタイムに動詞が揃っている。
3. `SSRANGE` 指定時の添字の範囲検査 (暫定判断 P-027)。
3. `DISPLAY` と実行の入口 (プログラムを起動する側)。
