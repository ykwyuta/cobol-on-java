# 設計 92 Java ソース出力

## 利用方法

CLI の `cobolc`、`plic`、`hlasm`、`cobolj` に `--emit-java` を追加する。
この指定時は `-d` を Java ソースの出力ルートとし、パッケージに対応する
パスへ UTF-8 の `.java` を書く。各言語の COPY、INCLUDE、コンパイラオプション、
HLASM のリスティング、JCL の PROCLIB 指定は同じ処理を通る。

Maven の `cobol:compile` と `cobol:jcl` では `-Dcobol.emitJava=true` で同じ
出力を選べる。出力ルートの既定値は `target/generated-sources/legacy`。
`cobol.javaOutputDirectory` で変更できる。このモードは移行用ソースの書き出しであり、
生成した Java のコンパイルと成果物への組み込みは利用側で設定する。
オプションを省略した場合は従来どおりプログラムのクラスを生成し、JCL は
CLI から直接実行するか、Maven で検査してリソースとして格納する。

## 生成方式

- COBOL は対応するプログラムを意味解析済みの手続きから直接生成する。対応範囲外のプログラムは
  既存のクラスのバイト列を [Vineflower](https://github.com/Vineflower/vineflower) で Java に戻す。
  選択はプログラム単位で行い、同じ原文内に両方式が混在できる。出力ルートには Java を書く。
- PL/I は前処理と検査を通した原文をテキストブロックに置き、`PliRuntime` の実行・署名・
  手続きマニフェストの呼出しを直接生成する。
- HLASM は組み立てた機械語と入口変位、再配置、外部参照を `ObjectModule` として直接生成する。
  機械語は行分けした Base64、再配置と外部参照は型付きの表で表す。
- COBOL・PL/I・HLASM の出力はパッケージ、クラス名、`CobolProgram` の呼出し規約を引き継ぐ。
  COBOL と PL/I の配備カタログには同じプログラム情報を載せる。PL/I の Java 出力では、
  生成した Java の内容からカタログのリビジョンを求める。再コンパイル時は対象言語の
  ランタイムをクラスパスに置き、配備カタログをクラス出力先へコピーする。
- JCL は現行の `JobDescription` で目録手続きと INCLUDE を展開する。
  展開した `Job`、`Step`、DD、条件を組み立てる Java を直接生成する。
  `.job` も同じ内部モデルから出力できる。クラスは `cobol.generated.job` に
  置き、`job()` でモデルを返す。生成クラスの `main` は `JobRunner` を使い、
  `-d`、`-w`、`-b` で実行時のパスを受け取る。
- 元のコンパイルやジョブ記述の検査で失敗した入力は生成対象から外す。
  逆コンパイルが失敗した場合はエラーとして返す。

## 可読性の改善

PL/I と HLASM は、生成クラスがランタイムへ渡す情報と実行の入口を読み取れる形にした。
COBOL の Java 出力では、意味解析で解決した手続き名を段落メソッドと `PERFORM`・`GO TO`
の行き先の定数に使う。記憶域参照では項目名から `OFFSET_` と `LENGTH_` の定数を作り、
添字や部分参照による位置のずれは、その基点に足す式で表す。同名項目は親の項目名で区別し、
Java の識別子へ変換した名前が重なる場合は接尾辞で区別する。これらの名前は Java 用の
中間クラスに残し、逆コンパイル後のメソッド宣言と呼出しに引き継ぐ。

```java
this.performRange(PARAGRAPH_MAIN_START, PARAGRAPH_MAIN_START, storage, context, arguments);
Ops.display(Ops.read(storage, OFFSET_WS_DISP_AMT, LENGTH_WS_DISP_AMT), context, true, false);
```

直接出力では、英字・英数字と固定小数点の作業場所項目を使う `MOVE`、`DISPLAY`、
`IF` を扱う。数値の読み書きと比較には共通ランタイムを使い、数値記述子は PICTURE、
USAGE、符号の位置と `TRUNC` を反映する。数値条件には固定小数点の算術式も使える。
`IF` の連言・選言・否定を Java の短絡演算にする。
`EVALUATE` の `WHEN` は意味解析で条件に展開し、Java の `if`・`else if` で
最初に一致した枝を実行する。`ALSO`、`THRU`、`ANY` は展開済みの条件を使う。
対応する作業場所項目の級条件は共通ランタイムの `ClassTest` を呼び、
数値の符号判定には `NUMPROC`・`NUMCLS` を反映する。
固定長の表では、各次元の要素長と 1 起点の添字からバイト位置を計算する。
部分参照は、開始位置と長さをそれぞれ式にする。長さを省いた場合は項目末尾までを使う。
国字項目では文字位置と文字数を 2 バイト単位で記憶域上の位置と長さに換算する。
`SSRANGE` では既存のクラス出力と同じ箇所で、変数添字や長さが定数の部分参照を検査する。
`INDEXED BY` の指標と `USAGE INDEX` の項目は、既存の記憶域表現で読み書きする。
`SET ... TO`、`UP BY`、`DOWN BY` は、意味解析で変換済みの転記・算術として出力する。
`SEARCH` は現在の指標から順に `WHEN` を評価し、最初の一致で終わる。
一致せずに進むときは指標と `VARYING` の項目を更新し、表を使い切ったときは `AT END` を実行する。
`SEARCH ALL` は探索範囲を二分し、各回で中央の位置を指標に格納する。
複合キーは宣言順に比較し、最初に異なったキーの昇順・降順に従って探索範囲を狭める。
見つからないときは最後に調べた位置を指標に残し、`AT END` へ進む。
`OCCURS DEPENDING ON` の表では、`SEARCH` の各反復と `SEARCH ALL` の開始時に現在の要素数を読む。
表より後ろにある項目の位置と、表を含む群を送るときの長さは、最大長で割り付けた位置や長さから
表の未使用分を引いて求める。群が転記を受け取るときは最大長を使う。
可変長の表が別の可変長の表に入れ子になる場合は従来の逆コンパイル経路で扱う。
`PERFORM TIMES` は回数を入口で一度だけ読み、`UNTIL` は `while` または `do ... while` にする。
単一の `PERFORM VARYING` では、`TEST BEFORE` は本体の前に検査し、`TEST AFTER` は
本体の後、カウンタを増やす前に検査する。
`ADD`、`SUBTRACT`、`MULTIPLY`、`DIVIDE` では、受取項目を書き換える前に被演算子を
一度ずつ読む。除算の桁数と丸めは受取項目ごとに決める。`COMPUTE` は式を一度評価し、
`ARITH` に応じた中間桁数を使ってから、受取項目ごとに丸めて格納する。
`ON SIZE ERROR` は、桁あふれした項目への書込みを止め、残りの項目の処理後に一度分岐する。
ゼロ除算で計算できなかった受取項目は元の値を保つ。
`DIVIDE ... REMAINDER` は商と剰余を格納前に求める。剰余の計算には商の受取項目の小数桁で
切り捨てた商を使う。`ON SIZE ERROR` のある文では、商があふれると剰余も格納せず、
剰余だけがあふれると商は格納する。算術文の受取側には通常の数字編集項目も使える。
`ADD`・`SUBTRACT`・`MOVE CORRESPONDING` は、意味解析で決まった項目の組を順に処理する。
算術文の `ON SIZE ERROR` は組全体で共有する。
`MOVE` の数字編集・英数字編集では、受取項目の `PICTURE` を名前付き定数として共通ランタイムに渡す。
数字編集項目を数値として読むときは編集を解く。英数字への転記では、符号付き整数の
表示形式から符号を除き、桁位置の `P` に応じて 0 を補う。群への転記では格納バイトを使う。
図形定数と `ALL` は受取項目に合わせて展開し、英数字編集の挿入位置は展開する長さに含めない。
国字の `MOVE`、`DISPLAY`、比較は共通ランタイムの UTF-16 変換、転記、比較を使う。
国字編集の挿入文字と `USAGE NATIONAL` の数字編集は、国字として扱う `PICTURE` で生成する。
数字編集から数値に戻すときは、国字用の編集解除を使う。
`ACCEPT` は入力レコード、日付、時刻を共通ランタイムから取得し、受取項目の分類に応じて
英数字または数値として転記する。入力レコードは受取項目の長さに応じた本数を読む。
`INITIALIZE` で翻訳時に値が決まる部分は、共通の初期化処理が求めた連続範囲ごとに
名前付きのバイト列を書き込む。`TO VALUE` はプログラムの初期イメージから値を取る。
データ項目を指定した `REPLACING BY` は意味解析で転記に展開する。
`STRING` は送出項目ごとに `DELIMITED BY SIZE` または区切り文字を指定し、宣言順に
共通ランタイムへ渡す。書いた範囲以外の受取項目は元の内容を保つ。
`WITH POINTER` の書き戻し後に、結果に応じて `ON OVERFLOW` または `NOT ON OVERFLOW` へ進む。
直接出力の段落メソッドは `GO TO` の行き先か、次の段落に流れ落ちることを示す値を返す。
`GO TO ... DEPENDING ON` は Java の `switch` で行き先を選ぶ。選択値が範囲外なら次の文へ進む。
`PERFORM` は実際に最後の段落を流れきった時点で戻る。途中で範囲外へ飛んでも実行を続け、
範囲へ戻らず手続き部の末尾に達した場合はプログラムの実行を終える。
`ALTER` と行き先を省略した `GO TO` は従来の逆コンパイル経路で扱う。
`NEXT SENTENCE` はラベル付きブロックを抜け、終止符の次の文へ進む。
`EXIT PERFORM` は最も内側のインライン `PERFORM` を抜ける。
`EXIT PERFORM CYCLE` は本体の残りを飛ばし、ループの条件判定やカウンタ更新へ進む。
`PERFORM UNTIL EXIT` は `while (true)` で表す。
`EXIT PARAGRAPH` と `EXIT SECTION` は、それぞれ現在の段落と現在の節の最後の段落を
流れきったものとして、`PERFORM` の範囲判定へ渡す。
`STOP RUN`、`GOBACK`、`EXIT PROGRAM` は共通ランタイムに委ねる。
同じプログラム内に対象外の文、節フック付きの `PERFORM`、副入口、別の記憶域モデルなどが
あれば、プログラム全体を従来の逆コンパイル経路へ渡す。既存のコード生成時の診断を両経路に適用する。

## 検証

各言語で CLI から Java を生成して `javac --release 21` で再コンパイルし、
従来の経路と標準出力、終了コード、呼出し結果を比較する。COBOL の副入口と
複数プログラム、PL/I の INCLUDE、HLASM のリスティング、JCL の PROC 展開、
インラインデータと実行条件を確認する。Maven では混在する資産の出力と既定モードを確認する。
